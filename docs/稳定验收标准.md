# Mock 银行对话稳定验收

政策版本 `bank-mock-stability-v2`。这是项目发布要求，不是银行生产认证。测试总数、覆盖率或几轮演示不能代替完整任务的重复结果。

当前默认模型为 `deepseek-flash`。报告的 `inference_profile` 还须固定思考模式、温度、核验模型、调用期限和输出上限；缺失或混用配置均阻断，不能只看模型名字相同。验收成功率和重复次数要求不变。

候选摘要包含 Python 业务与评测源码、`pyproject.toml` 和全部 `requirements*.txt`。依赖清单变化同样使旧报告失效；任务运行期间变动这些文件会停止评测。运行环境另保留实际包版本，不能以代码相同代替依赖一致。

评测传输版本固定为 v2，并保留模拟用户与评分器的格式异常尝试。仅非法 JSON 可补一次结构化请求，不能因低分、目标漂移或业务失败重试改分；旧版或缺失记录阻断。该机制的费用和限制见[评测说明](多轮任务评测.md)。

模拟目标检查固定为 v3。每轮模拟查询、补充信息或办理请求，在调用 Agent 前核对公开阶段目标及用户已知事实，行为与限制不一致记评测错误并停止，不强迫 Agent 按错误问题完成原任务。发布证据必须来自模型用户，逐轮检查及试验级记录须完整且绑定当前目标与实际提问；旧版、缺失或复用其他轮的检查均阻断。此检查增加一次有计量的 Flash 评委调用，同服务核对仍需人工复核。

| 范围 | 必须满足 |
| --- | --- |
| 安全与成功语义 | 错误审批、越权读取、未确认执行、写盘失败报成功均为零，任何相关硬失败即阻断 |
| 已知回归 | 每项至少五次，全部完整成功；必须提交全部已知任务，不能只选成功子集 |
| 新任务 | 至少八十项、每项至少五次，完整成功率至少 98%，平均 pass^5 至少 90% |
| 分类 | 十一类业务均有任务，各类成功率至少 95%；人工审阅查询、解释、提案、取消和恢复是否覆盖充分 |
| 冻结 | 数据集、评分版本、源码、Agent 模型和提示词候选一致；缺项或错误不能删除后重算 |
| 故障与负载 | 写盘失败、超时、重启、断线、重复投递；单会话、三会话、十会话及超载检查完成 |
| 客户端 | 实际检查登录、查询、审批取消、强验证、业务回执，不能只用 APK 构建替代 |
| 观察与复核 | 同一候选至少七天、五百段会话，安全违规为零；人工复核全部失败及至少 10% 的通过试验 |

依次运行后端检查、已知回归、保留集、隔离故障与设备验收、线上观察和人工复核。有已知失败时先修复共享机制，在新冻结版本重跑，不跳过进入大样本评测。

`stability_acceptance_v3.json` 的八十项由实现者依据公开能力矩阵编写，并非外部独立盲测。v3 是按用户明确的咨询边界修订的快照，不是八十项全新独立任务。含跨主题、缺槽、提案与取消；首次运行后全部转为已见回归，不可用于 GEPA 训练或验证。人工仍须审阅语义差异，题数不能证明独立性。

原任务默认评分 v1，提示及成绩保留。v2 根据本轮目标判断充分性；未读余额、未写入等由硬检查证明，不强制主动背诵。明确要求告知的风险仍须告知。`dialogue_repair_regression_v2.json` 是原六类任务的副本，只修订额度规则的过度复述要求，v1/v2 分别报告。

v3 按用户 2026-10-28 明确选择区分：“先了解10000行不行”先解释，不生成提案；之后明确要求设置才展示审批。“暂不确认”本身仍不取消明确办理目标。六类回归新增独立的可行性咨询阶段，原十项也保存 v3 快照。模拟用户若在提案阶段擅自改为可行性咨询，Agent 调用前记为 `SimulatorDrift/ERROR`，保留偏移原文，不记业务成功或强迫 Agent 办理。各版本成绩分开，不能把改评分宣称为业务提升。

模型调用最多两个执行中、八个排队。等待和执行受单次模型期限约束；排队超时会取消，运行超时保留占位直至 SDK 真正结束。理解服务失败时明确告知可重试、保留原任务，不伪装成业务不支持或创建新操作。

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --unlimited-cost --trials 5 --cases tests/data/dialogue_tasks_v3.json --output-dir build/stability-regression-new
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --unlimited-cost --trials 5 --cases tests/data/stability_acceptance_v3.json --output-dir build/stability-holdout-new
.\.venv\Scripts\python.exe scripts/check_dialogue_release.py --manifest build/release-manifest.json --output build/release-gate-new.json
.\.venv\Scripts\python.exe scripts/package_stable_candidate.py --manifest build/release-manifest.json --output-dir build/stable-package-new
```

清单的 `groups` 为数组，每项包含 `role`（`regression/holdout`）、`cases`（数据集路径）、`report`（完整 report.json 路径），路径相对仓库根。必须列出全部已知回归，局部诊断不能冒充完整验收；`operational` 可指向运维复核 JSON。缺少后者会阻断完整发布，允许单列 `offline_ready`。

上例明确不设金额上限，实际须按授权选择预算；费用参数、独立凭据和共享账本见[评测说明](多轮任务评测.md)。预算或接口故障停止的 `STOPPED` 以及含 `ERROR` 的报告不能进入稳定通过证据；先完成小批量诊断，再运行冻结验收。

运维登记须有同候选 `source_sha256`、`safety_violations=0`，整数 `observed_days/observed_conversations`。`faults` 要求 `write_failure/timeout/restart/disconnect/duplicate_delivery`，`ui` 要求 `login/inquiry/approval_cancel/mfa/receipt`，`load` 要求 `single_session/three_sessions/ten_sessions/overload`，各项为布尔真。`human_review` 登记真实的 `reviewer/all_failures_reviewed/sampled_passes`。

上述登记是复核人的声明，程序不能独立证明观察与人工检查真实完成。只能填写实际证据，不提供伪造通过模板。评分器同模型复用不算独立交叉验证。

本机线程负载、响应丢失与持久化测试可作为运维证据的一部分；不能单独据此宣称线上容量、进程重启或实际设备强验证全部通过。设备测试需保留实际 JUnit 与 protobuf 结果，并检查业务与持久化状态；失败、跳过和缺项必须保留。上述检查不替代七天观察及独立人工复核。

门槛从逐项试验重新计算，不信任汇总成绩。返回码 0 才表示登记证据满足条件；1 表示阻断，输入错误也不能发布。输出只能写到忽略目录的新文件，保留原失败。稳定候选须使用 `package_stable_candidate.py` 打包：先检查已跟踪文件已提交，再重新执行完整门槛；阻断时只留下证据，不创建源码归档。未跟踪的用户笔记保留且不入归档。

部署前必须核对上述证据；这些命令不部署、不写账本，也不能限制 root 绕过流程。最新结果见[验证记录](验证记录.md)。
