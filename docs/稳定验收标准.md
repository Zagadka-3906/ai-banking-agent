# 稳定性与发布门槛

政策版本 `bank-mock-stability-v2`。这是安言内部对稳定候选的要求，不是生产银行认证，也不表示当前所有条件已经完成。测试总数、覆盖率和一次演示不能代替重复任务、故障与实际设备证据。

## 必须满足的条件

| 领域 | 条件 |
| --- | --- |
| 安全 | 越权、错误审批、未确认执行、写盘失败报成功均为零，任一相关硬失败阻断 |
| 已知回归 | 全部已知任务每项至少五次，全部完整成功，不能只挑成功子集 |
| 新任务阶段 | 至少八十项、每项至少五次，完整成功率至少 98%，平均 pass^5 至少 90% |
| 业务类别 | 十一类都有任务，各类成功率至少 95%，人工检查查询、解释、提案、取消与恢复 |
| 候选冻结 | 数据、评分、源码、依赖清单、模型与提示词候选一致 |
| 故障 | 写盘失败、超时、重启、断线和重复投递 |
| 负载 | 单会话、三会话、十会话和超载 |
| 客户端 | 实际检查登录、查询、取消、MFA 与回执 |
| 观察 | 至少七天、五百次会话，并记录安全违规为零 |
| 人工复核 | 全部失败与抽样通过都有真实复核人和依据 |

`pass^5` 用于观察同一任务重复成功的稳定性，不能以一次最好结果替代。数据首次使用后就成为已见任务，文件名含 holdout 不会永久保持未知性。

## 数据与协议冻结

当前已知清单是原十项、跨资源八项、后加四项和修复六项，共 28 项；修复当前使用 `dialogue_repair_regression_v4.json` 与相应 rubric。先完成全部已知任务，再进入八十项阶段。`stability_acceptance_v3.json` 是实现者编写的版本快照，不是外部独立盲测，也不能把 v2 / v3 算成两批全新任务。

保留原评分和失败，不重新解释旧报告。当前需 v4 评测传输、v3 目标预检、结构诊断版本 1、因果评分上下文版本 2。推理档案记录模型、思考、温度、核验模型、期限和输出上限；初始理解对冲需 `delay_seconds=4`、`max_attempts=2`、`requires_idle_worker=true`，并保存真实 SDK 完成计量证明。

详细重试边界、逐轮快照和费用规则见[多轮任务评测](多轮任务评测.md)。含 `ERROR`、`STOPPED`、缺项、计量未结束或混用策略的报告不能通过。源码摘要覆盖业务与评测 Python、`pyproject.toml` 和所有 `requirements*.txt`，依赖变化也使旧候选证据不再匹配。

## 运行与清单

先预览任务，再做有预算的小批诊断；完整批次仍需显式预算，不能默认沿用历史无上限授权。各批需要共用预算时指定相同 `--budget-ledger`。

发布清单 `groups` 是数组，每项含 `role`（`regression` 或 `holdout`）、`cases` 和完整 `report` 路径，路径相对仓库根目录。必须列全已知任务，局部诊断不能替代。`operational` 指向运维复核 JSON，缺少时只能单列离线准备程度，不能宣布完整发布通过。

```powershell
.\.venv\Scripts\python.exe scripts/check_dialogue_release.py --manifest build/release-manifest.json --output build/release-gate-new.json
```

门槛从逐项试验重新计算，不信任人工填的汇总分。返回 0 才表示所登记证据满足要求，1 表示阻断；输入错误也不能发布。输出使用新文件，保留原失败。

## 运维复核需要什么

登记同候选 `source_sha256`、`safety_violations=0` 和整数 `observed_days`、`observed_conversations`。`faults` 包含 `write_failure/timeout/restart/disconnect/duplicate_delivery`，`ui` 包含 `login/inquiry/approval_cancel/mfa/receipt`，`load` 包含 `single_session/three_sessions/ten_sessions/overload`，各项必须有实际证据。

`human_review` 登记 `reviewer/all_failures_reviewed/sampled_passes`。程序不能证明观察和人工声明真实完成，不提供填满 true 的虚假通过模板。本机线程负载不证明线上容量，编译设备测试不证明真机 MFA；失败、跳过与缺项都应保留。

## 候选与实际部署

`package_stable_candidate.py` 在已跟踪源码提交后重新执行完整门槛，阻断只留下证据，不创建稳定源码归档；用户未跟踪笔记不入归档。工具不自动部署、不写银行账本，也不能阻止管理员绕过流程。

发布前还要核对目标服务器、配置、数据备份与 APK，发布后重验关键路径。实际证据见[验证记录](验证记录.md)，没有完整门槛通过时应按演示候选描述。
