# UI 与交互设计约定

2026-11-02 按当前源码核对。本文区分已有实现与后续建议，执行结果见[验证记录](验证记录.md)；原始设计方案可从 Git 历史查看。

## 交互原则

聊天承担咨询、提案和确认，二级面板用于浏览和预填。资金操作继续由 Core 预检、授权与提交，不能用动画或页面状态表示业务已经成功。已核验文本才能进入客户端呈现，金额与审批摘要按确定结果展示。

品牌使用暖石墨、浅金与米白，风险、涨跌和错误沿用各自语义色。界面和后台使用纯色，品牌原稿及对比度见[使用规范](brand/anyan-20261102/final/README.md)。

## 已实现的组件与行为

| 项目 | 源码与当前行为 |
| --- | --- |
| 数字排版 | `ui/theme/Theme.kt` 的各级文本样式启用 `tnum`，另有 `TextStyle.tabular()`；旧稿所称“仅标题已覆盖”已过时 |
| 回复与状态 | 已核验回复、结构化卡片和办理结果分别呈现；状态使用中文，读取加载与提交分别管理，避免重复提交 |
| 生日选择 | `ContactScreens.kt` 已有年、月、日滚轮、日期范围和闰年校验；不再把普通文本输入列为现状 |
| 联系人转场与删除 | 已有 `SharedTransitionLayout`；删除前弹窗核对姓名，确认后立即请求服务器，成功或只读核对后更新。页面重建保留确认对象，旧读取不得恢复删除记录 |
| 表单与通知 | 对应字段错误常驻，失败保留输入；通知进入独立展示队列，换账户清理。联系人删除不用撤销 Snackbar |
| 任务面板 | 人工处理确认在同一 Bottom Sheet 内切换，返回先退到列表；提交中保护导航，读取等待允许退出 |
| 申购金额 | 采用实际起购金额与十进制计算，已有步进、起购差额和费用估算；预填后回到聊天办理，不在底栏直接扣款 |
| 联系人补全 | 输入区已有联系人话术补全，不能把它扩写成模型自由生成并自动执行的指令 |
| 理财展示 | 五类 25 款产品、筛选和搜索、产品详情；单一完整集合在聊天去重。见[理财频道](理财界面.md) |
| 语音 | 底部面板长按说话、松开转写、上滑取消；实际 PCM 波形，识别文字核对后发送。见[语音输入](语音输入界面.md) |
| 历史筛选与思考动画 | 两栏筛选独立，滑块中途宽度约 110%；头像静止，旁边原生 shaping 点阵轮廓循环。见[交互细节](交互细节.md) |
| 信息密度 | 联系人使用轻量行式容器，理财风格指标用分组行与分隔线，大字体名称和数值可上下排列 |

相关源文件位于 `android/app/src/main/java/com/aibanking/agent/ui/`；JVM 边界样例可见 `UiEnhancementsTest`，设备测试按版本记录。

## 确认与权限

| 场景 | 约定 |
| --- | --- |
| 本人绿区查询 | 按会话和对象权限读取，结果核验后显示 |
| 黄区业务 | 展示服务端摘要，用户明确确认；不额外给日常转账添加逐条勾选或滑动仪式 |
| 红区业务 | 明确展示验证要求，由登记设备签名和演示 OTP 完成原协议；演示 OTP 自动获取不是真实短信认证 |
| 订阅查询 | 保留黄区确认，不能归入普通免确认查询 |
| 联系人删除 | 带姓名的前置确认、立即提交和服务器核对；取消或返回不发送删除 |
| 结果不明 | 查询原操作回执，不自动重做付款，不用乐观动画冒充成功 |

## 动效与无障碍

资金和事实过渡保持克制；不引入粒子彩带、3D 卡片翻转、霓虹品牌光效或实时大面积模糊。原生 Canvas 动画服从主题和减少动态效果设置，离开前台停止持续刷新。语音静音时波形保持平坦，不用随机动画模拟麦克风。

思考点阵只表示处理中，不作为付款进度或授权状态。审批和提交必须有可读文字，不能只依靠颜色、动效或触觉。大字体、短屏幕、明暗主题、TalkBack、返回与取消都需纳入实际设备验收。

## 后续建议与验收重点

以下是改进方向，不能作为已发布功能列入 README：

| 方向 | 完成条件 |
| --- | --- |
| 多会话管理 | 先确认会话生命周期与账号隔离，再评估抽屉搜索、置顶、重命名及删除撤销；首页继续进入当前对话 |
| 卡包横滑与弹层档位 | 评估多卡露边和半屏／全屏两档，保证当前选中卡与下方数据一致，返回行为清楚 |
| 图表与内联可视化 | 逐项核验曲线切换、资产占比和风险图形的数据来源，缺失值不能补零，图形不能替代风险说明 |
| 键盘与布局 | 真机检查输入框、导航栏与消息列表的同步，大字体下不遮挡确认信息 |
| 动效与语音验收 | 最终 shaping 版本补设备测试，真实麦克风与 ASR 另行评测；替身设备测试不作为准确率证据 |

每项改动先核对当前实现，再决定是否开发；验证应覆盖状态、业务回执和账号隔离，不能只检查截图。更多风险见[安全自评](安全自评报告.md)。
