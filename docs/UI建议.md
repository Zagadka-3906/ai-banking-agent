# 界面设计约定

安言以聊天表达目标，以结构化卡片承接确认和结果，以专门频道承接需要浏览和筛选的内容。界面应帮助用户判断“接下来会发生什么”，而不是让动画替代业务状态。[真实界面](../README.md#界面预览)

## 信息与视觉

暖石墨 `#30312D` 用于主要文字，米白 `#F6F3EB` 用于浅色背景，浅金 `#B39A68` 用于深底标志和少量点缀。风险、错误和涨跌沿用语义色，不把浅金用作浅底小号正文。Logo 直接使用[定稿资源](brand/anyan-20261102/final/README.md)。

一条回复先给结论，再给必要依据和下一步。金额、对象、期限、风险不能埋在装饰文字里。产品列表、持仓和回执采用对应卡片，单一完整产品集合不再由聊天正文重复列举；比较、混合业务、失败与不完整结果保留解释。

## 状态必须可区分

| 状态 | 展示要求 |
| --- | --- |
| 处理中 | 表示当前仍在读取或理解，可取消或等待；不得提前展示成功 |
| 需补充 | 明确缺对象、金额还是选择，保留已输入内容 |
| 待确认 | 展示具体业务、对象、金额与风险；确认和取消明确分开 |
| 需强验证 | 解释当前审批需要的设备验证，不把取消写成办理失败 |
| 部分完成 | 分别列出完成、阻塞、缺数据或失败项 |
| 已完成 | 对应服务端已保存回执；需要时提供核对入口 |
| 结果未知 | 说明正在或需要核对原回执，不自动引导重复付款 |

## 交互与无障碍

触控目标、选中状态和语义角色可被辅助功能识别。大字体下金额、风险和确认按钮不能被截断；横向分组允许滚动，不靠缩小字号强行塞满。深色模式逐项核对正文、卡片、图标与风险标识。

语音点击先开面板，长按采集、松开转写、上滑取消；转写只进草稿。页面离开前台后停止不必要逐帧刷新，尊重减少动态效果设置。关键确认不依赖单纯颜色、动画或触觉反馈。

## 修改界面时怎样验证

检查普通与大字体、明暗模式、键盘显示、滚动、系统返回和后台恢复。涉及业务卡片时，同时检查成功、失败、待确认、字段缺失和保存历史后的重新渲染。设备截图只证明对应构建的界面，不能代替授权测试和真实模型评测。

具体行为见[交互细节](交互细节.md)、[语音输入](语音输入界面.md)、[理财频道](理财界面.md)；验证命令见[测试用例](测试用例.md)。
