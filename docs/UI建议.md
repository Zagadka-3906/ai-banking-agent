## 一、总方向

**安静无边的色调画布 + 叙事文字流式晕染 + 处处等宽的数字 + 按语义分性格的动效。**

继续拒绝:弹跳、旋转、飞入、彩带、大面积模糊——银行产品的气质是"稳",动效克制换的是信任感。视觉语言维持 Gemini/Google 系简洁风格不变。

## 二、视频号"5 个质感细节"逐条评估

| # | 建议 | 结论 | 优先级 |
| --- | --- | --- | --- |
| 1 | 不画边框,靠 1%~3% 微对比色阶分层 | **采用为默认原则**(留功能性例外) | P2(现状已基本达标) |
| 2 | 暗色模式字重调细一档 | **可选彩蛋**(需中文验证,有备选方案) | P3 |
| 3 | 流式打字像水墨晕染,不要硬蹦 | **采用,混合式**(本清单价值最高) | P0 |
| 4 | 等宽数字防乱抖 | **无条件采用**(正确性问题,非品味) | P0 |
| 5 | 动效分性格:拖拽瞬时到位、反馈 Q 弹 | **采用原则、拒绝字面**(Q 弹不适配银行) | P1 |

### 1. 去边框,微对比色阶分层 —— 采用为默认原则

- 描边用多了是"廉价后台管理系统"的观感;色调分层是 Gemini/Google 系高级感的来源,与现有视觉语言同源。
- **保留两个例外**:输入框等功能性描边保留(边框在那里是交互提示,不是装饰);密集的回执/确认单保留分隔线(承担信息块边界的职责,全去掉牺牲可读性)。
- **暗色模式注意**:1%~3% 微对比在 OLED 深底上可能看不出层次,暗色端色阶步进要适当放大。
- 现状参考:主题已有完整 `surfaceContainer` 色调梯度,`BorderStroke` 仅用于输入框与 outlined 按钮变体,已基本符合本条。

### 2. 暗色模式字重降一档 —— 可选彩蛋

- 原理成立:浅字深底会视觉"发胖",降一档字重可找回精致感。
- **中文风险**:Android 实际渲染各厂商字体(MiSans、HONOR Sans 等),字重档位粗细不一,Medium→Normal 在部分机型上会显得"变瘦"而非"变精致"。
- **备选方案**:若跳档感明显,改用"次要文字降透明度/降对比度"实现同样的柔化效果,跨机型更稳。
- 定位:做了没人明说看得出,但暗色模式整体舒服一档。适合当答辩彩蛋,不值得优先投入。

### 3. 流式回复水墨晕染 —— 采用,混合式(价值最高)

- **理由**:本产品是 AI 智能体,回复的呈现过程就是产品核心体验。现在的"阶段进度 → 整段一次性出现"把 AI 产品最惊艳的时刻(答案流式展开、AI 显得"在思考在说话")换成了一个等待态;答辩演示观感差距大,且流式呈现能显著降低感知延迟。
- **混合式方案**(参考 ChatGPT/Gemini 官方客户端做法):
  - 叙事性文字:流式进场,新片段柔和淡入(晕染感),而非逐字硬蹦;
  - 事实内容(金额、审批卡片、数据面板):等后端算定后整体入场,不参与流式——既有生命感,又不牺牲金融数据的确定性;
  - 只对最新片段做淡入,规避表格/标题在半解析状态的重排抖动。
- 现状参考:ViewModel 已走 `streamMessage` 流式通道,"阶段进度"态可保留为数据未到时的前置状态。
- **这是建议清单里唯一动到核心交互模式的项,建议先做原型对比再全量铺开。**

### 4. 等宽数字 —— 无条件采用

- 与风格无关,是金融产品的正确性问题:余额、金额、净值、卡号数字在数值变化时横向抖动,专业金融机构的 app 里不存在。
- 现状缺口:`tnum` 只加在 `display*` 与 `headlineSmall` 样式;`CountUpText` 等数字动效不保证等宽,动画中必然抖动。
- **落地方案**:金额、余额、计数类文本样式全部补 `fontFeatureSettings = "tnum"`;`CountUpText` 默认合并等宽特性;必要时提供专用的"数字"文本样式。
- 与答辩 PPT 大纲"数字用 JetBrains Mono"同一原则——PPT 侧已做到,App 侧应拉齐。

### 5. 动效分性格 —— 采用原则、拒绝字面

- "拖拽瞬间到位"完全正确:手势跟踪类动效必须 1:1 跟手,不跟手的拖拽是廉价感的最大来源之一。
- "点赞 Q 弹"要过滤:弹跳是社交产品的多巴胺,转账确认按钮 Q 弹会直接伤害信任感。
- **落地为动效性格对照表**:

| 交互语义 | 动效性格 | 示例 |
| --- | --- | --- |
| 手势跟随(滑动、拖拽、进度) | 即时跟手,无延迟无过冲 | 预测返回、侧滑抽屉 |
| 状态确认(办理成功、审批通过) | 允许一次有节制的弹性表达 | 结果徽章的一次弹簧收束 |
| 资金相关(金额、转账、余额) | 克制精确,无弹性无娱乐化 | 金额入场、计数动画 |
| 微愉悦(语音按钮、答题完成) | 小幅弹簧即可,点到为止 | 按钮按压缩放 |

- 该思路与 Material 3 Expressive 的官方动效体系同构(标准弹簧 vs 表现弹簧两套 token),可借其 `MotionScheme` 落地,不必自造规格。

## 三、平台调研补充建议

1. **Material 3 Expressive 动效体系**(强烈建议):用官方 `MotionScheme` / `MaterialExpressiveTheme` 把动效节奏 token 化(现依赖版本已支持)。可顺带评估新组件(`LoadingIndicator`、`FlexibleBottomSheet`)替换现有加载态与底部面板。与"动效分性格"是同一件事的官方实现。
2. **Google Stitch + Gemini in Android Studio**(建议):Stitch 免费且 Gemini 驱动,适合新页面视觉探索(导出 Figma);Gemini in Android Studio 生成 Compose 代码。"AI 设计探索 → AI 生成 → 人工按规范收敛"本身是可写入答辩的工作流叙事。
3. **生成式 UI 架构叙事**(可选):agent 内联卡片机制(ChatCards/ChatWealth 等)本质是生成式 UI 的手写实现,可参考 Vercel AI SDK / CopilotKit 的"工具调用 → 类型安全组件 → 流式骨架"模式显式化重构,成本低、叙事价值高。
4. **设计规范提炼为 agent 提示词**(可选):视频号评论区"高定 UI 提示词"思路的本地化版本——从 `Theme.kt`、`DesignTokens.kt`、`ui/anim/` 实现与答辩 PPT 大纲的动效规则中提炼一份设计规范提示词/技能,让 AI 生成 UI 时自动遵守本项目约束,防"AI 味"。

## 四、优先级与落地清单

| 优先级 | 事项 | 验收标准 |
| --- | --- | --- |
| P0 | 等宽数字补全 | 金额/余额/计数样式全部 tnum;CountUpText 动画全程无横向抖动 |
| P0 | 流式回复混合式晕染(先原型) | 叙事文字流式柔和淡入;数据面板整体入场;无重排抖动;动效门控可用 |
| P1 | 动效性格对照表(可借 M3 Expressive MotionScheme) | 手势类 1:1 跟手;资金类零弹性;确认类至多一次弹性收束 |
| P2 | 色阶分层原则固化 + 暗色端色阶校准 | 装饰性描边清零;暗色模式层次可见 |
| P3 | 暗色字重降档试验(备选:降对比度) | 多机型对比无明显跳档感 |

## 五、明确不采纳的方向

- **弹跳/旋转/飞入/彩带**(Konfetti 等):银行克制气质,现有动效规则已明确排除,继续维持。
- **v0 / Lovable / Bolt / Figma Make**:输出 React/Tailwind,不产 Compose,仅可作视觉情绪板。
- **Rive / Lottie 资产管线**:管线重、学习成本高;现有自定义绘制动效(结果徽章等)已够用,不为此引入资产体系。
- **text-to-video 动效工具**(Firefly、Runway 等)与 Canva/稿定/美图设计室:面向视频与自媒体物料,与原生 App UI 无关。
