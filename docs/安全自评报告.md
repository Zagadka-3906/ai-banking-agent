# 安全自评报告

评估日期：2026-11-01。评估对象为 Android 客户端、Agent Gateway、Mock Core、本地及单机服务器面板、可选飞书私聊。仅使用虚构账户与交易，不代表银行生产安全认证。

## 权限分级实现

| 等级 | 典型业务 | 执行条件 |
| --- | --- | --- |
| GREEN | 本人余额、流水、卡片和业务解释 | 有效会话、对象归属与受限读取 |
| YELLOW | 小额转账、预约、AA、资金预留、订阅查询/取消、关闭渠道 | 前述条件，加预检摘要、明确确认和一次性授权 |
| RED | 当日累计超过 1000 元的转出、理财申赎、调额、开通渠道、冻结解冻和挂失解挂等 | 前述条件，加演示 OTP、登记设备签名及业务约束 |

Core 可结合行为升级风险，不能由模型或客户端降级。订阅查询保留确认协议。

`planner.py` 登记候选风险，Core 预检与执行端重新定级并校验主体、对象、金额、有效期及单次授权。客户端的风险标签、确认文本或“已验证”声明不能降低要求。私钥留在 Android Keystore，Core 验证登记公钥对 challenge 的签名。

查询与咨询只开放受限读取，模型没有账本写权限。订阅查询仍需确认。公网运维台与普通银行用户权限分开，其账户编辑能力只用于演示环境。

## 已完成的验证及范围

收尾业务版本 `cb37631`：后端 3101 项通过、1 项历史跳过；Android JVM 115 项、联系人与主题设备专项 24 项通过。负向用例覆盖跨主体、无会话、篡改、重放、非法金额、受限表达式、写盘失败回滚和无回执操作声明。单账户恢复与服务器更新前后核对了账本、设备、配置及证书。

这些结果是项目级自测证据，不能替代完整真机矩阵、第三方安全测试、真实银行合规审查或全部重复任务验收。

## 已知风险清单

| 编号 | 级别 | 风险和现状 | 缓解方向 |
| --- | --- | --- | --- |
| R1 | 高 | Mock 账本、会话与限流主要依赖单进程内存或本地文件；多进程/断电时无事务一致性保证。 | 生产化需事务数据库、共享会话与分布式锁；本项目仅单机运行。 |
| R2 | 高 | 演示账户及本机显示的一次性验证码不构成真实独立认证渠道；固定 OTP 仍供旧测试兼容。 | `.env.example` 推荐动态模式并禁用固定回退；仅用虚构账户，正式环境需真实身份与独立 OTP、密钥管理。 |
| R3 | 中 | 模拟器到宿主机的 HTTP 为明文，回环地址上的本机进程可观察/访问服务；本机恶意软件不在威胁模型内。 | 限定 `127.0.0.1`，正式部署需 TLS、访问控制与设备证明。 |
| R4 | 中 | 可选 DeepSeek 模型会接收当前输入、脱敏近期对话和经会话授权的事实证据，核验调用也会收到草稿与证据；脱敏与第三方数据处理未完成合规审查。 | 不输入真实个人资料；生产化需数据最小化、供应商审查和脱敏。 |
| R5 | 中 | Gateway checkpoint 可能短暂保存 MFA proof；本地库、设备注册表与账本快照属于敏感文件。 | 使用本机受限目录与系统磁盘加密；生产改为独立密钥库和短期凭证存储。 |
| R6 | 中 | 审计哈希链可发现部分篡改，但文件管理员可整体替换文件，缺少外部不可抵赖时间戳。 | 生产接入 WORM 日志、外部签名和集中告警。 |
| R7 | 中 | 沙箱执行规则模板或模型生成的账单分析表达式：AST 白名单、进程期限及 Windows Job / POSIX rlimit 限制工作进程资源（512 MiB、CPU 3 秒），工作进程跨调用复用、每 50 次任务或超时/崩溃后重建；仍没有独立文件系统和网络隔离。进程或限制安装失败时默认拒绝。 | 已实测资源限制安装及超额内存分配被拒、越权表达式被拒并审计；正式环境仍需 OS 安全隔离和最小权限。 |
| R8 | 低 | 熔断计数由 Core 统一维护，Gateway 拦截的注入经会话上报计入；限流与熔断状态在进程内存，重启后窗口重置；Core 不可达时注入上报失败只记审计，不阻塞拦截本身。 | 生产使用共享限流存储并监控异常。 |
| R9 | 中 | 模型可能误解、偏题、遗漏问题或生成无依据的解释；独立语义核验也可能误判，尤其同一模型的错误可能相关。 | 能力/知识版本化、讨论与审批分开；咨询仅开放有预算的十二类只读工具并限制 GET。自然回答引用绑定金额，核对字段、数字、编号及操作声明，另审业务范围、依据和逐项目标覆盖；缺口可在同一预算内补查，失败草稿不下发。读取失败与未回答不能标成全部成功；个人订阅读取仍须原确认，规则解释无需该确认。资金回执保持确定性，权限和提交由 Core 独立控制。回退单列，不能计作回答质量通过。详见 [Agent 架构](Agent架构.md)。 |
| R10 | 中 | AA 事件与任务待办在本机 API/应用内查询；飞书已完成文本、原生卡片和基础绑定查询验收，跨账户绑定、平台撤权与多成员覆盖仍未完成真实联调。 | 飞书 `open_id` 只能经一次性绑定码映射到已认证银行会话；私聊只读，IM 文本不得作为付款授权；见[飞书 IM 接入说明](飞书IM接入.md)。 |
| R11 | 低 | Core 私有 GET 的裸身份头漏洞已关闭；旧兼容测试中可显式关闭会话门禁，生产误设 `BANK_REQUIRE_SESSION=0` 会再次降低保护。 | 保持默认值 1，在启动自检和发布配置中验证。 |
| R12 | 中 | 订阅检测只从账本重复交易推断，可能把同额定期消费误判为订阅，也无法证明商户合同。 | 标记为待核实候选，显示流水证据；禁止对候选调用取消接口。 |
| R13 | 中 | 生日订单只有本机 Mock 商户回执，无真实履约、退款和商户对账；任务已随账本快照保存，仍没有跨进程持久事务。 | 明确展示 Mock 状态；正式接入需事务数据库、事务外盒、供应商签名回执与补偿流程。 |
| R14 | 中 | 飞书绑定持有与 App 同一登录的续期会话，到期前自动续期，App 退出登录即失效；绑定、去重与待回复队列仅在单进程内存，Gateway 重启会丢失；真实文本和原生卡片已由用户验证，平台撤权仍待验证。 | 单机演示限制为一个 Gateway worker；重启后重新绑定。生产化需共享安全存储与消息队列。 |
| R15 | 中 | 飞书私聊会显示虚构账户查询结果，飞书账号或客户端被他人控制时可能泄露信息；App Secret 放在本机 `.env`。 | 只接收私聊、会话短期有效、随时解绑；不使用真实个人资料，保护本机 `.env` 与飞书账号，生产化需额外设备和渠道风控。 |
| R16 | 中 | 无端侧识别的设备在用户同意后，会把一段语音（≤20 秒）经 Gateway 发送到阿里云百炼识别；语音可能含姓名、金额等信息，第三方数据处理未完成合规审查。 | 端侧识别优先；云端须首次明确同意（App 记住选择，清除应用数据可撤回），Gateway 校验同意头与会话、只收 16 kHz 单声道 WAV、限流，密钥只在 Gateway；录音不落盘，审计只记时长与字节数，不记音频或文字；识别结果只填输入框。默认 `qwen-audio-3.0-asr-flash` 会把“一百五”写成“150”、无法关闭，金额由用户在输入框和确认卡上核对；需要保留口语数字追问时改用 `qwen3-asr-flash`。 |
| R17 | 高 | 演示环境红区强度低于设计：任何已登录会话都可登记新设备公钥，演示验证码由接口返回并由 App 自动填入，因此口令泄露者可在演示环境完成红区操作。全部演示账户共用一个公开的演示口令。 | 仅用于虚构数据演示；生产需在登记新设备时校验独立短信码或已有设备签名并设冷却期、按用户限制设备数量、关闭验证码回显、每个账户独立口令。 |
| R18 | 中 | 提示词注入检测基于规则：已收窄为单一分句内的"绕过/跳过/解除…安全/验证/风控"等组合，正常用语误报显著减少，但仍可能误报或漏报，误报会计入熔断。 | 意图白名单、槽位校验与 Core 授权仍是主防线；持续补充误报回归用例。 |
| R19 | 低 | 熔断、限流、行为信号、MFA proof、会话线程锁等内存表只在过期或容量上限时清理，任意用户名会新建熔断记录；`/api/v1/security/health` 无需会话，公开活跃会话数、熔断人数等计数。设备表为全局容量上限，按最近使用淘汰。 | 单机演示可接受；生产需共享存储、定期清理、健康详情加管理员鉴权、按用户限制设备并保留吊销记录。 |

## 交付和使用边界

- 源码包排除真实配置、API 密钥、私钥、会话、账本、设备登记、日志与备份。公开 CA 证书可随演示安装包提供，CA 私钥不能分发。
- 服务器证书由项目 CA 签发，浏览器首次访问需信任该 CA；不宣称已获得公开受信证书。
- 视频使用隔离规则模式展示真实安卓操作，不将规则模式演示当作联网模型质量评测；红区片段只展示要求并取消，不冒充完成强验证。
- 飞书平台撤权与多成员覆盖、真人语音与用户体验统计、生产数据合规仍存在未完成范围。
- 风险未消除前仅用于虚构数据演示，不接入真实资金。
