# 多轮用户模拟与任务评测

本工具借鉴 [τ²-bench](https://github.com/sierra-research/tau2-bench) 的任务、用户模拟、环境结果和沟通评估分工，参考上游提交 `0c69df456a96aa76a1162591574dad9c427a34d7`。实现使用安言自己的任务格式与 Core/Gateway，不安装或复制上游评测代码，不是官方 banking domain，也不产生可与其排行榜比较的分数。

## 任务与角色

`tests/data/dialogue_tasks.json` 保存有版本的合成任务。每项包括用户目标、人物、已知事实、初始条件、有限阶段和私有评分标准。现有十项覆盖可疑交易连续追问、解冻步骤、小额强验证、生日联动、切换话题、混合与范围外请求、缺槽任务续办、待审批插问、转账后查流水及有限额度。它们来自已知问题与产品边界，是开发回归集，不是独立盲测集。

| 角色 | 可见信息 | 权限 |
| --- | --- | --- |
| 自适应模拟用户 | 当前阶段目标、人物、用户已知事实、可见对话与确认摘要 | 只生成下一句用户文本，不读账本、不看评分标准、不调用工具 |
| 固定用户对照 | 每阶段预设文本 | 按固定说法重放，用于区分表达变化与链路问题 |
| 被测 Agent | 正常 Gateway 请求、本人会话和既有受限工具 | 与实际产品相同，不获取任务评分标准 |
| 确定性环境检查 | 每轮前后全量业务集合、任务、授权表、Core 调用方法与审批绑定 | 直接判定状态和行为，不依赖模型自述 |
| 事后评分器 | 任务标准、可见对话、可信知识及合成账户证据 | 只评分，不参与生成答复或授权 |

阶段目标约束模拟用户，前一轮答复决定它如何自然追问。模拟用户不能自行结束任务、跳过未完成阶段或决定确认任意操作。确认与取消由测试驱动按任务明确执行；确认驱动只接受本人向李四转 300 元、金额与收款人均匹配的黄区提案。调额红区只验提案与取消，不自动提供 OTP 或设备签名。

## 开发、保留与回归分开

2026-10-28 新增[稳定发布门槛](稳定验收标准.md)。数据集可显式登记 `rubric_version=v1/v2`，报告与评测子进程保留该版本，未登记时继续 v1；不得把 v2 的评分提示应用到旧 v1 成绩。新增八十项能力矩阵任务只是实现者编写的首次保留集，运行后转回归，不是独立盲测。

原十项 `dialogue_tasks.json` 是开发集。`dialogue_holdout.json` 为八项跨资源任务，首次运行后已暴露；`dialogue_generalization.json` 为实现冻结后新增四项，首次运行后同样转为回归。后者由实现者编写，不是独立盲测。两组首次结果、修改后的复跑与旧链路对照分别报告，不能把重试成绩称为未见泛化。

数据集 `split` 与 SHA256 写入报告。子集执行种子按原数据集位置计算，筛选任务不会改变相同任务种子；自适应用户仍会随答复改变表达，因此旧/新链路不保证逐字相同输入。评分器可信证据包含交易时间、本人任务与安全测评档案，避免跨月误评分；模拟用户依然看不到这些证据与评分标准。逐项目标状态和 FIELD_FALLBACK 单列，不能把规则回退计为自然生成或完整回答。

## 评分

阶段新增可选 `required_reads`、`answered_goals` 中间检查点与 `goal_shift` 标记。检查点直接核对 Core GET 及逐项覆盖状态，语义评分不能覆盖硬失败。报告记录 `intermediate_milestones`、`goal_shifts`、`within_turn_duplicate_gets` 和 `turn_latency_ms`；目标切换的当轮完成需同时满足硬检查与该阶段语义检查，重复读取计数只作诊断，不自动判错。

任务通过要求环境与行为检查、沟通检查都通过。不会要求所有正确实现走完全相同的只读工具序列，也不会因回复含有“验证码”等关键词就判成功。

- 每轮查询必须不改变账本、任务与授权，不发 Core 写请求；存在待审批时保持句柄、主体、摘要、授权绑定及有效期。用户已提出但缺金额的办理请求单列为 `clarify`，只额外允许语义只读的 `POST /payees/check`，仍不得签发授权或改变业务。提案不能提前执行，取消后资金不变。
- 结束状态须符合目标。转账任务核对双方余额精确变化、一对金额/方向/账户/商户匹配且编号唯一的流水、日累计及其他业务不变；只读和取消任务要求最终业务状态不变，账本持久化健康。
- 事后评分逐阶段判断是否回答具体问题、是否重复旧答、是否误拒绝业务、是否编造时限或已执行操作。自然度另记为辅助评分，不覆盖硬检查。
- 模拟用户偏离目标记为 `ERROR / SimulatorDrift`；评分器格式错误、模型异常、缺少观测和试验未完成也单列。硬规则不通过即停止后续办理，仍可评估已发生对话中的用户偏移。
- `answer_modes` 记录服务端展示标记，核验自然回答总数以其 `GENERATED_REVIEWED` 为准。`answer_kinds` 补充回答与审批上下文分类：携带原审批的插问也归入 `APPROVAL_OR_RECEIPT`，可同时有自然回答标记；`SCOPE_OR_CLARIFICATION` 包括范围说明与澄清，不能一概算拒绝。无审批的显式安全回退另记为 `SAFE_FALLBACK`，其他无标记回复须结合正文复核。安全回退不能算作核验自然回答；自然回答数量也不是完整任务通过数量。另统计连续完全相同的答复供排查，不因文本相同直接判失败。

对每个任务重复运行 `n` 次，有 `c` 次完整成功时，使用 **pass^k = C(c,k) / C(n,k)**，衡量抽取 k 次全部成功的稳定性；它不是“多试几次至少成功一次”的 pass@k。例如四次成功三次时，pass^1 为 0.75、pass^2 为 0.5、pass^4 为 0。先对每项任务计算，再对任务取平均；错误、缺失或试验不足时相应指标为 `null`，不悄悄删掉失败记录。公式参考[上游实现](https://github.com/sierra-research/tau2-bench/blob/0c69df456a96aa76a1162591574dad9c427a34d7/src/tau2/metrics/agent_metrics.py)。

## 运行与产物

新增 `dialogue_repair_holdout.json` 六项任务由隔离的模型作者根据能力及预先指定任务类型生成，作者没有获得源码或 Agent 运行轨迹。首跑前修正格式和产品前提，原始草稿保留；不称为外部独立盲测。首跑后转为回归。重复运行可使用 `--cases tests/data/dialogue_repair_holdout.json --trials 3`，分别报告首次、重复及错误，不取最好一次替代稳定性。

可选离线 GEPA 使用不同的 development 训练、验证任务，拒绝 holdout；`--prompt-bundle` 仅在隔离评测子进程安装候选，摘要写入报告，运行期间改变候选会使评测报错。候选不会自动发布，命令与边界见[对话可靠性改造](对话可靠性改造.md)。

先安装 `requirements-dev.txt`。预览无需密钥、不会启动银行服务或调用模型：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --dry-run --trials 2
```

明确使用真实模型、模拟用户与事后评分器：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --trials 3 --output-dir build/dialogue-eval-model-20261025
# 固定用户对照；Agent 与评分器仍调用真实模型：
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --user scripted --trials 3 --output-dir build/dialogue-eval-control-20261025
# 可重复添加 --task，只执行选中任务：
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --task suspicious_followups --task task_resume --trials 2 --output-dir build/dialogue-eval-subset-20261025
```

输出必须使用仓库忽略的 `build/` 下新目录，保留旧运行证据，不覆盖旧报告。`report.json` 记录任务、数据集 SHA256、Git 版本和工作区是否有改动、模型名称、种子、逐轮文本、Core 方法/路径与硬检查、语义评分及汇总；`summary.md` 便于阅读，每个 trial 的 JSON 可独立排查。候选业务与评测源码记录逐文件 SHA256，试验期间代码或数据集变化会使运行报错，不混为同一候选结果。进程每完成一项即保存报告，中断留下未完成计划。退出码：0 为完整通过或明确的预览；1 为任务未通过；2 为模型、模拟用户、评测或观测不完整。预览标为 `PLAN_ONLY`，不能计入通过次数。

`DEEPSEEK_API_KEY` 为被测 Agent 密钥；默认用户和评分器复用该服务与主模型，可单独配置：

| 变量 | 含义 |
| --- | --- |
| `BANK_EVAL_USER_MODEL` / `BANK_EVAL_JUDGE_MODEL` | 模拟用户模型与事后评分模型；未设置时复用 `BANK_LLM_MODEL` |
| `BANK_EVAL_USER_BASE_URL` / `BANK_EVAL_USER_API_KEY` | 可选模拟用户独立服务；未设置时复用 DeepSeek 服务 |
| `BANK_EVAL_JUDGE_BASE_URL` / `BANK_EVAL_JUDGE_API_KEY` | 可选评分器独立服务；未设置时复用 DeepSeek 服务 |

只向模型发送合成任务、可见对话和必要的合成事实；不发送会话令牌、签名或授权材料。种子用于标识模拟变体，不保证模型服务逐字可复现。用户温度为 0.8，事后评分为 0，被测模型使用产品自身配置。复用同一模型会有相关错误；独立服务配置只是提供比较条件，不等于已经做过模型优选。没有密钥、模型错误或评分错误均不能报告为通过。

## 隔离与边界

每个任务的每次试验使用独立子进程和临时账本、设备库、checkpoint、审批及审计目录。导入应用前禁止自动读取 `.env`，强制使用这些临时路径、本人登录鉴权，关闭后台调度、飞书与语音。Core/Gateway 经进程内真实 HTTP 客户端交互，银行传输拒绝外部地址，不连接现有本机或服务器银行服务。临时数据库关闭后清理；不重置共享账本，也不自动部署应用。

当前只评测文字任务及一项黄区资金执行，不等同于手机 Compose/SSE、真实语音、飞书、红区验证、写盘故障或生产安全验收；原有设备与协议回归仍分别运行。LLM 评分可能错判或被对话影响，需抽查失败、成功与边界案例，逐步加入未参与修复的保留集、人工复核和更多真实问法。评测结果只能用于该任务集、模型及代码版本。
