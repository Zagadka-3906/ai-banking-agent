# 多轮任务评测

安言将一次任务拆为多个用户阶段，检查理解、咨询、补充、提案、取消与恢复是否形成完整过程。工具使用隔离的 Core / Gateway、模拟用户、硬状态断言和独立语义评分，不以聊天流畅度代替业务正确性。

设计借鉴 [τ²-bench](https://github.com/sierra-research/tau2-bench) 中任务、用户模拟与环境评估的分工，参考提交 `0c69df456a96aa76a1162591574dad9c427a34d7`。实现采用自己的任务格式和模拟银行，不是其官方 banking domain，分数不可与该排行榜直接比较。

## 角色与因果边界

| 角色 | 能看到 | 不应看到 |
| --- | --- | --- |
| 模拟用户 | 当前阶段公开目标、必要事实与已发生对话 | 私有评分标准、预设答案、尚未到达阶段的意图 |
| 被测 Agent | 实际用户消息、产品自身上下文和受控工具 | 任务私有评分要求 |
| 目标预检 | 原始事实、当前目标和实际模拟提问 | 不得修改原话后强行判为目标一致 |
| 语义评分器 | 本轮及之前对话、该轮目标与当时可信环境快照 | 后续问题、后续目标或最终状态回流到早先评分 |
| 硬检查 | 实际 Core 请求、账本、审批、执行与权限状态 | 不依靠模型自行声称通过 |

提案阶段只提出对象、金额和办理请求，不提前说“我确认”；查询阶段不擅自加入暂停、提交或取消指令。目标预检区分恢复办理提案与询问提案规则，偏移记 `SimulatorDrift/ERROR`，保留原文，不把错误问题交给 Agent 后强迫完成原任务。

## 任务数据

任务记录阶段目标、初始状态、模拟用户事实、硬断言和私有评分要求。当前模拟协议使用 `simulation_profile` 表示静态身份和事实，`simulation_facts` 按阶段释放临时金额或条件，避免提前泄露后续计划。

静态与阶段事实各最多十条，每条 1–180 字；缺省使用中性登录用户，不从混合 persona 自动抽取未来意图。原始目标与事实保留供独立预检。所有版本固定摘要，格式调整或评分修订不能回填旧成绩。

| 数据 | 用途与来源 |
| --- | --- |
| `dialogue_tasks*.json` | 十项开发任务及评分快照 |
| `dialogue_holdout.json`、`dialogue_generalization.json` | 八项跨资源与四项后加任务，首跑后转为已见回归 |
| `dialogue_repair_regression*.json` | 六类修复任务，版本副本不算新任务 |
| `dialogue_repair_holdout.json` | 六项后加任务，不称外部独立盲测，首跑后转为回归 |
| `stability_acceptance_v*.json` | 八十项稳定验收快照，由实现者编写，版本更新不等于新独立样本 |

训练、development 验证和 holdout 分开。GEPA 不接受 holdout 作训练或验证；已参与修复的数据不得重新宣传为未知泛化任务。详见[数据目录](../tests/README.md)。

## 先预览，再决定是否联网

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --dry-run --trials 2 --output-dir build/dialogue-plan-new
```

预览标为 `PLAN_ONLY`，不调用模型、不计为成功。命令输出必须使用 `build/` 下新目录，保留原失败与历史报告。

真实调用示例需要有效模型配置，会消耗额度；下例使用 10 元估算预算，实际可按自己的任务调整：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --max-cost-cny 10 --trials 1 --stop-on-failure --output-dir build/dialogue-live-new
```

`--cases` 指定数据，`--task` 可重复筛选，`--seed` 标识模拟变体，`--concurrency` 控制并发。`--user scripted` 是固定用户对照，Agent 与评分仍可调用真实模型，不能当作免费运行。局部诊断不能冒充完整稳定验收。

## 独立模型配置

可复制 `.env.eval.example` 为私有 `.env.eval`，以 `--eval-env-file .env.eval` 加载。配置只作用于评测，不修改服务器；缺项仍沿用主配置。

| 变量前缀 | 用途 |
| --- | --- |
| `BANK_EVAL_AGENT_MODEL/BASE_URL/API_KEY` | 被测 Agent 的模型、服务与凭据 |
| `BANK_EVAL_USER_MODEL/BASE_URL/API_KEY` | 模拟用户 |
| `BANK_EVAL_JUDGE_MODEL/BASE_URL/API_KEY` | 目标预检与语义评分 |

不同 Key 仍可能共用供应商余额，不代表财务隔离。同模型的用户、Agent 和评分器可能共享偏差，独立调用不等于独立评估。种子不保证远端模型逐字复现。

## 评分与完整性

硬检查确认是否越权读取、错误审批、未确认执行、错误提交或状态不一致。语义评分检查切题、依据、自然度与当前目标覆盖；硬失败不会被高语言分抵消。缺证据的安全回退不是任务完整成功。

当前协议要求以下记录齐全：

- v4 评测传输记录格式与接口异常尝试；非法 JSON / 用户结构最多共享一次修正，评分结构错误不重试；临时传输故障最多相同输入重发一次，逻辑请求最多三次调用。低分、目标漂移、认证失败和额度不足不能借重试改分。
- v3 模拟目标检查绑定每轮真实提问与阶段，不覆盖原文或强制修改 verdict。
- `judge_schema_diagnostics_version=1`，受限结构诊断正常应为空；错误不保存输入值、供应商正文或模型原文。
- `judge_context_version=2`，逐轮深拷贝环境快照，来源和阶段匹配，不读取后续状态改判前轮。
- `inference_profile` 固定模型、思考模式、温度、核验模型、期限和输出上限。初始理解对冲为约四秒、最多两次相同输入、仅空闲容量时追加，共享十二秒期限，不按答案优劣选响应。
- 逐项保存 `model_calls_completed=true` 的真实 SDK 结束计量；晚到响应只补计量，不改答或改分。

这些要求约束当前证据，缺失的历史记录不能补写成新协议通过。评分标准 v1 / v2 / v3 和任务副本分别报告，不能把评分修订称为业务能力提升。

## 费用与停止条件

真实运行必须明确金额预算或显式选择无金额上限。默认还有 2,000 次模型请求和单次 4,096 输出 token 保护，可用 `--max-model-calls`、`--max-output-tokens` 调整。保护参数本身影响评测条件，须记录。

`--price-file` 可提供模型到 `{input_cached,input_uncached,output,context_tokens}` 的映射，前三项为每百万 token 人民币单价，最后为上下文上限。内置价是代码中登记时点的估计，不是动态报价；第三方模型和未定价别名需显式设置实际价格。金额限额约束估算与预留，不能保证供应商实际账单。

调用前按上下文与输出上限保守预留，返回后从真实 SDK usage 结算；未知用量或超时保留预留值，不记免费成功。思考 token 如已含在输出总量中不重复收费。多个批次通过同一 `--budget-ledger build/<campaign>/budget.sqlite3` 共享预算与故障状态，换账本不能用于掩盖累计消费。

`cost.run` 与 `cost.campaign` 记录本批和整个活动的调用、返回、token、缓存、未知用量和费用。`summary.stage_usage` 分阶段汇总；缓存比率为命中输入 token 占已知输入 token 比例，不是命中请求比例。供应商缓存、预热与清理不受本工具保证，旧账户答案仍需重新取证。

鉴权、无效请求和额度不足等确定性错误立即停止；连续三次模型接口错误、连续三个试验错误、子进程故障或源码变化也停止。`STOPPED` 保留未运行项并返回 2，不能进入稳定通过证据。已发出请求仍可能收费；`--stop-on-failure` 可用于首个业务失败后停止诊断。

## 产物与隔离

`report.json` 保存数据摘要、Git 信息、模型、种子、逐轮可见文本、请求与硬检查、评分及费用；`summary.md` 用于阅读，每项 trial 可单独排查。源码、候选提示词、依赖清单或数据在运行中变化会停止，不能拼成同一候选成绩。

每任务每次试验使用独立子进程、临时账本、设备、会话、审批与审计，导入前关闭自动读 `.env`、后台调度、飞书与语音。银行请求通过进程内真实 HTTP 客户端，拒绝访问外部银行地址，不重置共享服务。外部模型只接收必要的合成任务和对话，不发送令牌、设备签名或授权材料。

退出码 0 表示完整通过或明确的计划预览，1 表示业务任务未通过，2 表示接口、模拟、评分或观测不完整。预览、跳过、错误和未运行均不能算成功。

## 从诊断走向发布

先保留失败并修复共享机制，再冻结数据、源码、模型与评分配置。离线优化候选通过 `--prompt-bundle` 安装到评测子进程，不自动发布。发布门槛见[稳定验收标准](稳定验收标准.md)，实际运行范围见[验证记录](验证记录.md)。

当前文字评测及部分黄色资金用例不覆盖完整手机 Compose / SSE、真实语音、飞书、红区强验证、写盘故障和线上容量，这些必须另行验证。
