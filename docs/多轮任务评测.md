# 多轮用户模拟与任务评测

本工具借鉴 [τ²-bench](https://github.com/sierra-research/tau2-bench) 的任务、用户模拟、环境结果和沟通评估分工，参考上游提交 `0c69df456a96aa76a1162591574dad9c427a34d7`。实现使用安言自己的任务格式与 Core/Gateway，不安装或复制上游评测代码，不是官方 banking domain，也不产生可与其排行榜比较的分数。

## 任务与角色

只查询阶段另带公开的 `inquiry_phase_contract`：仅表达当前目标，保留已有意向，未要求时不加入暂停、提交、确认或取消指令。可以询问撤单或提交规则，不能把规则问题扩写为要求现在操作。契约不含私有评分标准或预设答案；输出原文继续接受独立目标预检。即使核对返回 `faithful=true`，`expected_act` 与 `actual_act` 不符仍阻断，目标漂移不改写、不重试成通过。

契约另显式声明 `approval_hold_preserves_proposal`：目标中的不确认或继续暂不确认，表示保留原审批等待确认，不能扩写为不转、不办或取消原业务。此项不改变预检的行为分类；违规原文继续保留为 `SimulatorDrift`。

当前默认 `deepseek-flash`，本机 Agent、核验、模拟用户和评分器均为 Flash。`BANK_MODEL_THINKING` 默认 `disabled`，空值跟随服务商默认；显式 `enabled` 须另行评测期限与输出上限。12 秒调用期限、4096 输出 token 上限、思考模式和核验模型进入 `inference_profile`；发布检查拒绝缺失或混用这些配置的报告。历史 Pro 诊断与旧别名成绩不归为 Flash 成绩。

评测传输版本为 `evaluation_transport_version=4`。模拟用户或评分器返回非法 JSON/非对象时，最多补一次仍受 JSON 对象约束的格式请求；v4 起模拟用户返回不符合 `{"text"}` 消息结构的 JSON 对象（`SCHEMA_INVALID`）也共用这一次格式修正，评分器结构不符仍不重试，发布检查拒绝评分器的 `SCHEMA_INVALID` 记录；另对指定临时 API 故障允许一次相同输入重发，两类合计最多三次调用，详细边界见下文。每次尝试计量并保存受限诊断，低分、目标漂移与业务失败不重试改分。发布检查拒绝旧传输版本或缺失尝试记录，历史报告不重判。

`tests/data/dialogue_tasks.json` 保存有版本的合成任务。每项包括用户目标、人物、已知事实、初始条件、有限阶段和私有评分标准。现有十项覆盖可疑交易连续追问、解冻步骤、小额强验证、生日联动、切换话题、混合与范围外请求、缺槽任务续办、待审批插问、转账后查流水及有限额度。它们来自已知问题与产品边界，是开发回归集，不是独立盲测集。

| 角色 | 可见信息 | 权限 |
| --- | --- | --- |
| 自适应模拟用户 | 当前阶段目标、人物、用户已知事实、可见对话与确认摘要 | 只生成下一句用户文本，不读账本、不看评分标准、不调用工具 |
| 固定用户对照 | 每阶段预设文本 | 按固定说法重放，用于区分表达变化与链路问题 |
| 被测 Agent | 正常 Gateway 请求、本人会话和既有受限工具 | 与实际产品相同，不获取任务评分标准 |
| 确定性环境检查 | 每轮前后全量业务集合、任务、授权表、Core 调用方法与审批绑定 | 直接判定状态和行为，不依赖模型自述 |
| 事后评分器 | 当前阶段标准、截至该轮的对话、该轮与更早的可信环境快照 | 每轮独立评分，不看后续问题、后续目标或最终账本，不参与生成答复或授权 |

阶段目标约束模拟用户，前一轮答复决定它如何自然追问。模拟用户不能自行结束任务、跳过未完成阶段或决定确认任意操作。确认与取消由测试驱动按任务明确执行；确认驱动只接受本人向李四转 300 元、金额与收款人均匹配的黄区提案。调额红区只验提案与取消，不自动提供 OTP 或设备签名。

模拟用户输入按背景事实、历史对话、变化种子、本轮请求类型和当前目标组织，当前目标放在最后；不重复发送总体计划。公开请求类型只区分查询、办理、澄清等本轮行为，不暴露评分标准、预期账本或工具路径。背景中的后来取消、历史助手对先前咨询的答复不能覆盖本轮明确办理。模拟用户温度仍为 0.8，独立目标预检不接收该类型提示，而是从阶段目标另行判断，不重抽偏移提问或重判原错误。

环境不预热日累计日期桶。查询或预检不得初始化、清空或更新业务计数；跨午夜查询也须保留原账本，仅返回当日投影。计数与日期的变更只在实际扣款事务中接受完整状态和持久提交检查。

## 开发、保留与回归分开

2026-10-28 新增[稳定发布门槛](稳定验收标准.md)。数据集可显式登记 `rubric_version=v1/v2/v3`，报告与评测子进程保留该版本，未登记时继续 v1；不得把新评分提示应用到旧成绩。v3 按用户选择区分先问可行性与明确要求办理，并在 Agent 调用前识别提案阶段模拟用户改成咨询的偏移。八十项能力矩阵是实现者编写的首次保留集，运行后转回归，不是独立盲测；各版本副本不算不同的八十项任务。

原十项 `dialogue_tasks.json` 是开发集。`dialogue_holdout.json` 为八项跨资源任务，首次运行后已暴露；`dialogue_generalization.json` 为实现冻结后新增四项，首次运行后同样转为回归。后者由实现者编写，不是独立盲测。两组首次结果、修改后的复跑与旧链路对照分别报告，不能把重试成绩称为未见泛化。

数据集 `split` 与 SHA256 写入报告。子集执行种子按原数据集位置计算，筛选任务不会改变相同任务种子；自适应用户仍会随答复改变表达，因此旧/新链路不保证逐字相同输入。评分器可信证据包含交易时间、本人任务与安全测评档案，避免跨月误评分；模拟用户依然看不到这些证据与评分标准。逐项目标状态和 FIELD_FALLBACK 单列，不能把规则回退计为自然生成或完整回答。

## 评分

模型用户在当前目标仅要求查询或解释时，不得为衔接话题额外说取消、暂停、放弃或修改先前办理；等待确认与放弃办理分开。只有当前目标自己要求停止时才表达停止，不能从背景中的最终决定提前引入。目标预检仍独立比较行为，混合取消与查询不因 `faithful=true` 就当作纯查询；偏移原文保留为错误，不重写后重试、不交给银行执行、不重算旧成绩。

报告登记 `judge_schema_diagnostics_version=1`，每次试验保留 `judge_schema_diagnostics`，正常为 `[]`。独立目标预检和逐轮评分若触发结构校验错误，记录逻辑请求序号、阶段类别、当前评分轮号（预检无轮号）、最多八项白名单字段路径与错误类型、响应 SHA256 及 `retried=false`；未知字段名用占位替换，不存输入值、错误上下文、供应商正文或原始回复。结构错误仍立即为 `ERROR`，不重试评分、不调整合法负分、不重算旧报告。提示明确 reason 为 1—500 字符、布尔及自然度的实际 JSON 类型，仅约束现有结构，不改评分标准。发布检查拒绝旧版本、缺少或不合法诊断，以及带结构错误却声称通过的试验。

`judge_context_version=2` 固定逐轮因果评分。驱动在每次实际步骤结束后深拷贝当时环境，并以阶段编号保存 `judge_context`；评分器逐轮独立调用，只接收该轮目标、问题、回复、硬检查、当时可信快照和此前对话／快照。完成后的最终余额与后续追问不回流到早先阶段，避免要求用户当时尚未询问的消费合计，或用转账后的余额否定此前查询。每轮一个语义判断，不以低分重判；硬失败仍立即停止后续办理。发布检查拒绝旧版、缺快照、阶段错配或空快照，历史报告保留。

环境快照另保留当轮 `query_context.date_scope/date_range`，它描述图中的查询上下文，不单独证明发生 GET。实际读取仍按调用轨迹及硬检查判断。评分须遵守当前日期、对象和承接的列表范围；“那笔”在多候选中没有唯一选择时，可以合理澄清，不能根据“最可能”或范围外交易猜定用户指代。

普通“帮我办理／给某人转账”是请求提案，不是确认授权；目标写“暂不确认”时，不要求用户逐字复述等待。只有明确提前确认、授权立即执行或要求跳过确认才违反该限制。评分按当前用户明确要求检查漏答；可信账本中存在其他字段，不自动将它们列为必答。新增独立逐轮调用计入 Flash 评委费用与调用上限，同模型评分仍不能代替人工复核。

报告分别记录 `goal_evidence_check_version=2` 和 `simulator_goal_check_version=3`。模拟用户生成的查询、补充信息及提案请求，均先用独立的评委提示核对本阶段公开目标、已知事实及此前用户消息；不提供助手答复、私有评分标准、固定示例问句或账本结果。核对分别输出目标行为、实际提问行为及事实限制是否一致，取消与继续办理不能相互替代。两类行为不一致或忠实度为假，在调用 Agent 前记为 `ERROR / SimulatorDrift`，不重抽提问或重试判断。接口或结构异常同样记错误，不能继续调用 Agent。

每次尝试保留阶段、实际提问与核对结果；成功核对另保存目标和提问的 SHA256。发布检查要求逐轮及试验级记录完整、一致、摘要绑定当前目标与提问，并拒绝旧版本和脚本用户成绩。原有 v3 提案阶段的显式流程咨询偏移检查仍保留。旧报告、旧失败不重新改判，新评测源码必须冻结后另建输出目录。

本轮行为只由 `current_goal` 定义。核对先仅据该目标归纳预期行为；已知事实只约束身份、对象、数值等背景，不能把“后来、最终取消”等后续计划提前套到本轮办理或查询。事后评分也逐阶段使用对应目标，不用总体结局覆盖中间阶段。此类评分器修订须保留旧错误，用新候选重新评测；单独的评分器正反例校准不得充作银行任务通过数。

每轮模拟输入额外增加一次 Flash 评委调用，纳入既有 `judge` 角色的 token、费用、传输异常与请求上限；无语义重试。当前传输为 v4，预检和事后评分采用不同上下文，但共用 Flash 服务，不能算跨模型或人工独立验证，也不能保证识别全部目标偏移。

传输 v3 保留 v2 的一次非法 JSON 格式修正，并允许一次明确 API 传输重发：仅超时、连接故障或 HTTP 408、429、500、502、503、504，认证错误、参数错误和明确额度不足不重试。API 重发使用完全相同的消息和 JSON 对象约束；格式修正仍保留原任务，仅增加格式说明。同一逻辑请求两类各最多一次，总调用最多三次，SDK 自身重试保持关闭。每次均独立预留并结算费用；未返回用量的失败继续保留保守预留，不当作免费调用。诊断仅存请求序号、尝试序号、受限错误代码、返回字数和是否重试，不保存供应商错误正文。发布检查同时验证版本、记录结构、顺序、类别和次数，成功试验不得包含终止异常。合法 JSON 的低分、目标偏移和业务失败不会触发重发；连续失败仍保留错误并停止批次。Agent 的模型期限、银行工具和业务执行不使用此重试。

模拟提示要求已知事实仅作背景，不能将背景中的其他咨询提前带入当前办理阶段。使用 `--stop-on-failure` 时，首个 `FAIL` 或 `ERROR` 均停止整个共享账本的后续试验；分别记录 `TASK_FAILED` 或 `TRIAL_ERROR`，已有接口或预算停止原因保留。未启用此参数时，仍保留原有连续三次试验错误停止机制；错误不能被删掉后重新计算。

每轮 `answer_diagnostics` 只包含同请求最多三项审核拒绝代码和尝试次数；不含原始解析状态、供应商错误正文或私有审计载荷。该字段仅供诊断，不修改评分。Agent 的 JSON 格式绑定仍保留费用代理，所有调用继续先预留额度、结算实际 token 并共享停止状态；接口不支持格式时不追加自由文本重试。

阶段新增可选 `required_reads`、`answered_goals` 中间检查点与 `goal_shift` 标记。检查点直接核对 Core GET 及逐项覆盖状态，语义评分不能覆盖硬失败。报告记录 `intermediate_milestones`、`goal_shifts`、`within_turn_duplicate_gets` 和 `turn_latency_ms`；目标切换的当轮完成需同时满足硬检查与该阶段语义检查，重复读取计数只作诊断，不自动判错。

任务通过要求环境与行为检查、沟通检查都通过。不会要求所有正确实现走完全相同的只读工具序列，也不会因回复含有“验证码”等关键词就判成功。

事后评分同时接收按阶段编号绑定的实测意图、是否存在审批和硬检查结果，包括硬失败提前停止时已发生的阶段。它们不包含预设沟通分数，也不向模拟用户开放。评分须区分必需行为、可选方式与禁止行为：标准中的“可逐项询问”不能变成强制逐项或固定顺序，“进入澄清”不要求向客户宣读内部流程名称，未写入等限制由实测证明。对应硬检查失败时不能依据助手措辞推翻；硬检查全部通过也不能代替回答完整性和事实准确性。理由须有实际回复或观测依据，不能因缺少标准原句而扣分。真实模型正反例校准单列费用与原判，不计入任务验收成绩。

2026-10-28 后续评测登记 `goal_evidence_check_version=2`：询问阶段明确带有 `NEEDS_DATA` 的目标覆盖时，硬检查 `goal_evidence_complete` 不通过，正面模型评分不能覆盖。`TOOL_FAILED` 只有本轮实际 GET 失败且资源路由匹配时允许进入语义评分；是否满足故障说明场景仍由任务标准判断，其他失败不算成功。环境记录与发布检查器独立复核逐轮覆盖及同资源 HTTP 故障证明，防止用伪造 PASS 隐藏未完成证据。既有澄清、待确认和明确不支持仍按各阶段标准判断。此前 v1 一律拒绝 `TOOL_FAILED`，误拦了预设接口故障的说明任务；旧报告和原判保留，不重算，不同源文件及检查版本不能混成同一候选成绩。

- 每轮查询必须不改变账本、任务与授权，不发 Core 写请求；存在待审批时保持句柄、主体、摘要、授权绑定及有效期。用户已提出但缺金额的办理请求单列为 `clarify`，只额外允许语义只读的 `POST /payees/check`，仍不得签发授权或改变业务。提案不能提前执行，取消后资金不变。
- 结束状态须符合目标。转账任务核对双方余额精确变化、一对金额/方向/账户/商户匹配且编号唯一的流水、日累计及其他业务不变；只读和取消任务要求最终业务状态不变，账本持久化健康。
- 事后评分逐阶段判断是否回答具体问题、是否重复旧答、是否误拒绝业务、是否编造时限或已执行操作。自然度另记为辅助评分，不覆盖硬检查。
- 模拟用户偏离目标记为 `ERROR / SimulatorDrift`；评分器格式错误、模型异常、缺少观测和试验未完成也单列。硬规则不通过即停止后续办理，仍可评估已发生对话中的用户偏移。
- `answer_modes` 记录服务端展示标记，核验自然回答总数以其 `GENERATED_REVIEWED` 为准。`answer_kinds` 补充回答与审批上下文分类：携带原审批的插问也归入 `APPROVAL_OR_RECEIPT`，可同时有自然回答标记；`SCOPE_OR_CLARIFICATION` 包括范围说明与澄清，不能一概算拒绝。无审批的显式安全回退另记为 `SAFE_FALLBACK`，其他无标记回复须结合正文复核。安全回退不能算作核验自然回答；自然回答数量也不是完整任务通过数量。另统计连续完全相同的答复供排查，不因文本相同直接判失败。

对每个任务重复运行 `n` 次，有 `c` 次完整成功时，使用 **pass^k = C(c,k) / C(n,k)**，衡量抽取 k 次全部成功的稳定性；它不是“多试几次至少成功一次”的 pass@k。例如四次成功三次时，pass^1 为 0.75、pass^2 为 0.5、pass^4 为 0。先对每项任务计算，再对任务取平均；错误、缺失或试验不足时相应指标为 `null`，不悄悄删掉失败记录。公式参考[上游实现](https://github.com/sierra-research/tau2-bench/blob/0c69df456a96aa76a1162591574dad9c427a34d7/src/tau2/metrics/agent_metrics.py)。

## 运行与产物

模拟用户和事后评分器通过 [JSON 对象输出模式](https://api-docs.deepseek.com/guides/json_mode/) 请求结构化响应，报告登记 `evaluation_response_format=json_object`。这只约束评测角色的接口格式，不改变银行 Agent 的模型配置或评分标准。返回内容仍须经过 JSON 与任务 schema 检查；接口不支持、截断、格式错误和用户偏移仍记 `ERROR`，不把普通文本自动包装成成功，不为获得通过成绩重复请求。

2026-10-28 诊断曾复现模拟用户直接返回自然语言，导致 Agent 尚未调用就出现 JSONDecodeError。受影响批次和中止原因保留，不能把这些错误算成银行业务失败，也不能从分母删除后声称通过。修复评测传输后必须冻结新评测源文件并使用新输出目录重新运行。

新增 `dialogue_repair_holdout.json` 六项任务由隔离的模型作者根据能力及预先指定任务类型生成，作者没有获得源码或 Agent 运行轨迹。首跑前修正格式和产品前提，原始草稿保留；不称为外部独立盲测。首跑后转为回归。重复运行可使用 `--cases tests/data/dialogue_repair_holdout.json --trials 3`，分别报告首次、重复及错误，不取最好一次替代稳定性。

可选离线 GEPA 使用不同的 development 训练、验证任务，拒绝 holdout；`--prompt-bundle` 仅在隔离评测子进程安装候选，摘要写入报告，运行期间改变候选会使评测报错。候选不会自动发布，命令与边界见[对话可靠性改造](对话可靠性改造.md)。

先安装 `requirements-dev.txt`。预览无需密钥、不会启动银行服务或调用模型：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --dry-run --trials 2
```

明确使用真实模型、模拟用户与事后评分器：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --unlimited-cost --trials 3 --output-dir build/dialogue-eval-model-new
# 固定用户对照；Agent 与评分器仍调用真实模型：
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --unlimited-cost --user scripted --trials 3 --output-dir build/dialogue-eval-control-new
# 可重复添加 --task，只执行选中任务：
.\.venv\Scripts\python.exe scripts/evaluate_dialogue_tasks.py --live --unlimited-cost --stop-on-failure --task suspicious_followups --task task_resume --trials 2 --output-dir build/dialogue-eval-subset-new
```

输出必须使用仓库忽略的 `build/` 下新目录，保留旧运行证据，不覆盖旧报告。`report.json` 记录任务、数据集 SHA256、Git 版本和工作区是否有改动、模型名称、种子、逐轮文本、Core 方法/路径与硬检查、语义评分及汇总；`summary.md` 便于阅读，每个 trial 的 JSON 可独立排查。候选业务与评测源码、`pyproject.toml` 和全部 `requirements*.txt` 记录逐文件 SHA256，试验期间代码、依赖清单或数据集变化会使运行报错，不混为同一候选结果。进程每完成一项即保存报告，中断留下未完成计划。退出码：0 为完整通过或明确的预览；1 为任务未通过；2 为模型、模拟用户、评测或观测不完整。预览标为 `PLAN_ONLY`，不能计入通过次数。

长时间真实评测使用独立、持久的隔离作业，先校验已提交代码包、逐文件摘要和数据集摘要，再安装独立依赖并运行检查。服务器任务限定并发、CPU 和内存，将生产目录挂为只读，仅向工作区与临时账本写入；只有模型凭据进入评测进程，业务服务配置不继承。聊天中断后核对实际作业与报告，不能仅凭旧 `RUNNING` 快照声称仍在运行，也不能删除未完成项拼成通过。全部 28 项各五次通过后，才进入 80 项各五次评测；失败保留并停止，最后重新执行发布门槛，不自动部署。当前任务的提交、位置和状态见[验证记录](验证记录.md)。

`DEEPSEEK_API_KEY` 为被测 Agent 密钥；默认用户和评分器复用该服务与主模型，可单独配置：

| 变量 | 含义 |
| --- | --- |
| `BANK_EVAL_AGENT_MODEL/BASE_URL/API_KEY` | 覆盖评测子进程的 Agent 配置，不修改父进程或服务器；空值沿用主配置 |
| `BANK_EVAL_USER_MODEL` / `BANK_EVAL_JUDGE_MODEL` | 模拟用户模型与事后评分模型；未设置时复用 `BANK_LLM_MODEL` |
| `BANK_EVAL_USER_BASE_URL` / `BANK_EVAL_USER_API_KEY` | 可选模拟用户独立服务；未设置时复用 DeepSeek 服务 |
| `BANK_EVAL_JUDGE_BASE_URL` / `BANK_EVAL_JUDGE_API_KEY` | 可选评分器独立服务；未设置时复用 DeepSeek 服务 |

可复制 `.env.eval.example` 为忽略文件 `.env.eval`，用 `--eval-env-file .env.eval` 指定；独立环境文件中的配置优先于本次进程环境，只作用于评测。缺项仍沿用主配置，报告登记配置来源，不能据此认定已经财务隔离。不同 Key 若同属一个账户也可能共享余额，应使用独立账户或服务商提供的项目预算。

## 费用记录与停止条件

`summary.stage_usage` 按理解、字段核对、规划、生成、核验及其他调用汇总缓存用量，`cache_hit_ratio` 为命中输入 token / 已知输入 token，不是请求命中次数或各请求百分比的简单平均。输出不保存请求内容。费用代理保留 SDK 与绑定中的思考参数，再应用输出上限，防止评测丢失显式模式。固定规则目录与资源定义前置；生成及核验中的已验证条款按编号排序前置，当前账户记录仍重新读取，问题、反馈与候选正文后置。不填充无关条款。[供应商缓存](https://api-docs.deepseek.com/guides/kv_cache/) 仍受前缀持久化、预热和清理影响，不保证固定命中率，也不复用旧账户答案。

2026-10-28 起，真实评测与 GEPA 必须明确选择 `--max-cost-cny <金额>` 或 `--unlimited-cost`。后者表示不设金额上限，符合用户本轮授权；默认仍有最多 2000 次模型请求、每次最多 4096 个输出 token 的保护，可分别配置 `--max-model-calls` 与 `--max-output-tokens`。上限改变了评测输出条件，报告中的 `cost.limits` 保留配置；不得与旧的无上限批次混算稳定性。

`report.json` 的 `cost.run` 和 `cost.campaign` 分别记录本批及共用账本的请求、返回、输入/输出 token、缓存命中/未命中、未知用量和估算或预留费用，按 Agent、核验、模拟用户、评分器和优化反思区分。费用不是服务商账单。思考 token 已包含在输出总数，不重复计费；缺少用量时停止并保留预留费用，不记为免费成功。

计价读取 SDK 的 `usage_metadata/response_metadata.token_usage`，字段依据 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。内置价格仅为 [2026-10-28 官方公开价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 中 `deepseek-flash` 与 `deepseek-v4-pro` 的人民币高峰档估算；不是动态报价，不自动为 `deepseek-chat` 等旧别名猜价。未定价模型可在无金额上限时记录 token，但金额为 `null`；设置金额上限前必须提供所有模型的显式价格，第三方服务也应提供其实际价格。

`--price-file build/eval-prices.json` 的内容是模型名到 `{input_cached,input_uncached,output,context_tokens}` 的映射：前三项是每百万 token 的人民币单价，末项是实际服务上下文上限。启用金额上限时，每次调用前按整个配置上下文及输出上限、未命中价格保守预留，返回后按实际用量结算，因此可能提前停止。超时或费用不明保留预留值；该机制约束配置估算，不能保证服务商实际账单。多个批次须传同一 `--budget-ledger build/<campaign>/budget.sqlite3` 才共享总预算和故障状态；GEPA 内部评测及反思自动共用。不同账本互不限制，不允许用更换账本掩盖既有消费。

按 [官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)，余额不足、鉴权及无效请求等确定性错误立即停止；连续三次模型接口错误、连续三个试验错误、子进程故障或源码变化也停止。状态记为 `STOPPED`，保留已完成、错误、未运行项，退出码 2，不能通过发布门禁；已经发出的请求可能仍消耗额度。`--stop-on-failure` 另可在首个业务失败后停止定向诊断，不建议用大批全量运行定位单一缺陷。共享账本不会自动清除停止状态或重试失败请求。

本轮用户允许付费并明确不限制金额，因此实际运行使用 `--unlimited-cost` 和小批量定向任务，不重开全部历史评测。没有设置新的模型或将服务器配置切换为另一服务。

只向模型发送合成任务、可见对话和必要的合成事实；不发送会话令牌、签名或授权材料。种子用于标识模拟变体，不保证模型服务逐字可复现。用户温度为 0.8，事后评分为 0，被测模型使用产品自身配置。复用同一模型会有相关错误；独立服务配置只是提供比较条件，不等于已经做过模型优选。没有密钥、模型错误或评分错误均不能报告为通过。

## 隔离与边界

每个任务的每次试验使用独立子进程和临时账本、设备库、checkpoint、审批及审计目录。导入应用前禁止自动读取 `.env`，强制使用这些临时路径、本人登录鉴权，关闭后台调度、飞书与语音。Core/Gateway 经进程内真实 HTTP 客户端交互，银行传输拒绝外部地址，不连接现有本机或服务器银行服务。临时数据库关闭后清理；不重置共享账本，也不自动部署应用。

当前只评测文字任务及一项黄区资金执行，不等同于手机 Compose/SSE、真实语音、飞书、红区验证、写盘故障或生产安全验收；原有设备与协议回归仍分别运行。LLM 评分可能错判或被对话影响，需抽查失败、成功与边界案例，逐步加入未参与修复的保留集、人工复核和更多真实问法。评测结果只能用于该任务集、模型及代码版本。
