本轮检查覆盖 Python Core、授权与会话、Gateway／Agent 工作流、任务调度和持久化、Android 数据与界面层、飞书接入、启动脚本及 CI 配置。重点是错误重试、重启恢复、身份隔离和验证流程，未进行大规模架构调整。

## 已修复

| 问题 | 原有表现 | 本轮处理 |
| --- | --- | --- |
| 并发回滚后的旧账本引用 | 转账等待结算时另一失败事务替换内存记录，可能出现扣款与入账不一致 | 账户与任务等可变状态在事务锁内读取；补普通转账与预约结算的并发资金守恒测试 |
| 任务未随账本保存 | 预约记录重启后仍在，对应任务却查询不到，无法继续执行或取消 | 将任务 ID、依赖、状态和幂等索引纳入签名快照；任务结算回执可重启恢复；补异常回滚与损坏快照测试 |
| 业务变更后的幂等重试 | 取消订阅或冻结卡成功后，同键重试被新的业务状态拒绝 | 先读取同一主体、同一请求的已完成回执；不同请求复用键仍拒绝；历史回执深拷贝，避免被后续状态覆盖 |
| 消息去重缓存过期 | 已完成转账重投原消息编号，仍拿到旧审批卡 | 确认、取消和结果核对后同步关联消息缓存；复合任务推进到当前审批；缓存读取与结算使用同一会话锁 |
| 会话续期与退出语义不一致 | 续期后原审批失败，退出又遗漏仍有效的旧凭据 | 同一次登录的续期凭据共享稳定登录身份；退出撤销该次登录的全部凭据；独立登录保持隔离 |
| 请求体上限仅信任请求头 | 无长度或少报长度的请求可绕过限制 | Core／Gateway 共用实际字节计数；超限立即停止读取；保留合法请求体供路由解析；断连返回客户端错误 |
| 健康探针不支持默认登录要求 | 开启严格会话后余额探测返回 401 | 探针先登录指定演示账户，检查余额并退出自己的临时会话；支持登录 OTP |

兼容边界：旧账本快照中没有保存过的任务无法可靠重建，加载时不会猜测、重新发送提醒或下单；需人工核对旧预约与锁资记录。密码变更保留原有回放路径。本项目仍是单机 Mock，以上修复不提供跨进程／跨机器事务保证。

## 仍需继续处理

1. **优先处理 Android 切换账户时的在途响应。** `ChatViewModel.logout()` 清空界面和凭据，但普通聊天、卡片等请求没有统一取消，也未统一验证请求发起时的登录身份。A 请求延迟、退出并登录 B 后，A 的回包可能写入 B 的当前界面。建议引入登录代次校验及会话协程取消，补延迟回包的账户切换测试。本轮通过代码路径确认，未做模拟器复现；相关文件已有未提交界面改动，留待与该批改动一起处理。
2. **飞书分类账单条件需要完整传递。** 本地解析能识别“分析本月餐饮支出”的餐饮分类，但飞书固定查询路径仅使用日期，可能展示全月全分类支出。应把分类传给分析接口，或明确提示改用 App。该文件已有未提交改动，本轮未混入修复。
3. **飞书卡片改动需要同步测试。** 当前工作区的绑定等回复从字符串变为 `FeishuReply`，4 个测试仍使用字符串包含断言；另有 App 名称断言需随文案更新。应与对应卡片实现一起提交，避免测试和接口不同步。
4. **后续工程完善。** 文档声明支持 Python 3.10–3.12，CI 目前只验证 3.12，可补运行时矩阵。`main.py` 同时承担 HTTP、账本、授权编排和任务状态，后续新增业务前可按边界逐步拆分。模拟器 UI 测试应继续使用隔离账本，减少跨用例状态影响。

本轮未连接真实银行、未调用在线模型、未执行真实飞书消息发送；未重新运行模拟器 UI 插桩流程或在线依赖漏洞审计。
