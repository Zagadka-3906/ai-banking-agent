# 文档维护

公开文档面向想了解、运行和扩展安言的读者。README 解释项目价值、体验和上手路径，专题文档承接实现细节；正文不以早期材料模板或维护者私有部署为前提。

## 事实从哪里来

| 信息 | 首要依据 |
| --- | --- |
| 业务与权限 | Core 业务校验、授权协议和对应回归 |
| 模型、参数与功能开关 | `.env.example`、配置加载和实际调用代码 |
| 启动与服务器路径 | `scripts/serve_local_panel.py`、`deploy/` 脚本 |
| Android 行为 | 当前状态机、Compose 组件和设备用例 |
| 规则与能力目录 | `banking_knowledge.py`、`banking_rules.py` 与同源 JSON |
| 测试结果 | 指定提交、设备、模型、命令和原始报告 |
| 品牌与界面 | 定稿 SVG 与实际应用截图，概念图需明确标注 |

不能从实现愿望推断已支持，不能从健康 200 推断完整业务可用，也不能把历史测试数贴到新版本上作为新验收。

## 更新顺序

1. 确定改变的是用户行为、配置、协议还是验证结果。
2. 更新最接近该主题的文档，再检查 README、导览与交叉引用。
3. 规则或能力变化先修改同源实现，再运行导出，不直接编辑生成正文。
4. 核对限制、失败路径和取消语义，保留确定程度与实际执行范围。
5. 检查链接、图示、命令和渲染，只提交公开需要的文件。

```powershell
.\.venv\Scripts\python.exe scripts/export_banking_rules.py --check
.\.venv\Scripts\python.exe scripts/check_repository_docs.py
```

新增文档和图片先加入 Git 索引再做链接校验，检查器以已跟踪文件为准，不依赖本机恰好存在的私人文件。

## GFM 展示约定

README 使用 GitHub 原生支持的表格、提示块、Mermaid、`details/summary` 和 `picture`。头图提供明暗 SVG；界面使用本地 WebP，动态导览使用 GIF 并保留静态替代。所有图片写清替代文本，避免强制动画。

不依赖任意 CSS、JavaScript、iframe 或 SVG 脚本，GitHub 会清理不受支持内容。HTML 与 Markdown 混排时保留必要空行；折叠区内正文写 Markdown，摘要写简单文本。参考 [GitHub 基本语法](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)、[折叠区](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections)及[图示](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)。

本地预览用于发现裁切、溢出和对比问题，最终仍核对 GitHub 页面。自动链接检查验证本地目标与图像源，不代替远端链接可达性、锚点语义、Mermaid 渲染或内容正确性。

## 保留兼容与历史

部分中文文件名和早期脚本名保留为兼容路径，页面标题已改为当前公共用途。`AGENTS.md` 属于协作规则，不是产品宣传文档；第三方许可证不随文案润色重写。运行产物、个人笔记和交付材料不因文档维护自动同步。
