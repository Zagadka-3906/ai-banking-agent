## 人工处理与任务依赖

1. 在任务页选择尚未执行的任务，点击“请求人工处理”，填写原因并核对说明。
2. Core 在账本锁内先检查任务归属、终态、关联锁资、依赖分支及是否有正在执行的步骤。
3. 有正在执行的关联任务时拒绝本次接管，先核对结果；拒绝不会只暂停一半分支。
4. 检查通过后，将相关待执行节点置为 `HUMAN_TAKEOVER`，保存原因并写审计。调度器不会继续运行这些节点。
5. 页面提供任务编号、依赖状态、原因与人工处理说明。负责人据任务编号核对回执；新的资金操作须重新预检和授权。

分支变更及持久化由同一内存事务包裹；落盘失败恢复原状态，并在同一追踪号记录 `PERSISTENCE_FAILED_ROLLBACK`，避免只留下先前允许决策而看不到失败收尾。

已完成的资金操作不会随接管撤销。锁资不会因为请求人工处理自动释放；解锁仍需原有授权流程。这里提供的是人工交接入口，没有后台客服坐席或自动接单服务。

## 飞书本轮验收

用户在真实私聊发送“本轮验收”，未收到回复。SDK 事件处理中取得租户访问令牌失败，返回 `21001`，提示平台访问策略拒绝。随后只读探针调用官方租户令牌接口，HTTP 200、业务码 21001、没有获得令牌。这个结果不能证明卡片渲染通过，也不能确定具体是哪项账号或企业策略。

追加排查中用户确认有企业管理后台，当前应用 App ID 与本机一致。环境代理配置与独立直连请求均仍为 21001。进一步核对平台原始错误提示要求联系 customer support，探针精确映射为 `policy_hint: contact_platform_support`。尚未取得命中规则，不能把拒绝归因于账号类型、某个企业开关或 IP 白名单，管理员应优先向平台支持索取具体规则及恢复条件。

`scripts/diagnose_feishu_access.py --compare-network --output build/feishu-diagnostic/report.json` 输出检查时间、HTTP 状态、业务码、是否取得令牌和经过格式验证的 Log ID / Request ID，不输出 Secret、令牌或响应原文。`feishu_im.bot_status` 提供最近发送失败的安全诊断字段，不回显 SDK 异常中的 URL、令牌或消息正文。

管理员具体入口、最小权限、审核发布、策略核对及支持工单模板见[飞书 21001 排查与恢复验收](飞书IM接入.md#21001管理员排查与恢复验收)。独立运行 `scripts/feishu_acceptance.py --output-dir build/feishu-acceptance-新轮次 --wait-for-access-seconds 3600`，可先等待访问恢复，再进行文本和原生卡片验收。该脚本只响应明确的“本轮验收 / 验收通过 / 验收失败”，不查询账户、不发起业务，分别记录文本发送、卡片发送和人眼确认；用每轮盐化编号代替真实发送者 ID。任一发送失败、没有人工回复、旧轮次或其他参与者回复均不能完成当前验收。日志保留每次运行，拒绝覆盖既有目录。

平台恢复后仍需逐项验收：银行账户绑定、余额与分类账单一致、无匹配结果、群聊无账户回复、重复事件只回复一次、错误绑定码、会话过期、App 解绑、平台撤权、离线恢复。发送一张静态验收卡片不替代这些业务验收。
