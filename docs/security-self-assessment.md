# 安全自评报告（演示沙箱）

> 版本：2026-09-12。本文是参赛交付材料，不等同于生产银行系统的合规认证。演示数据均为虚构数据。当前代码已落地服务端 MFA、签名 token、口令登录与会话吊销（登出）、设备公钥信任根、锁资解锁、审计、熔断和幂等；账本/审批/设备库/审计链支持可选 HMAC 校验落盘。下列生产化风险仍需评审。

## 1. 资产、信任边界与威胁模型

**受保护资产**：账户余额、锁定金额、交易流水、联系人映射、一次性授权凭证、审计事件和模型 API 密钥。

**信任边界**：浏览器/Streamlit（不可信）→ Agent 编排层（半可信）→ Core Banking API（唯一记账边界）。浏览器中的按钮、隐藏字段和模型生成文本都可能被篡改；只有核心服务端策略和凭证验证可以授权资金变更。

**主要威胁**：

1. Prompt injection 诱导模型把查询改成转账或伪造成功结果；
2. 盗用/伪造/重放 token，篡改收款人或金额；
3. 绕过前端直接调用 API，绕过红区 MFA；
4. 负数、NaN/Inf、并发请求或重试造成超扣/锁资异常；
5. 账户枚举、流水泄露、日志泄露验证码/密钥；
6. 连续失败、自动化攻击或核心依赖不可用导致业务失控。

## 3. 已有控制与证据

- **决策/执行分离（加强版）**：`agent.py`/`planner.py` 负责意图和路由，`main.py` 执行余额变更；执行接口要求签名 `x-auth-token`，并由 `security.py` 校验绑定和策略。
- **一次性凭证与 MFA proof**：凭证采用 HMAC 签名和 TTL，成功结算后 token/proof 标记 `used`，可阻止重放；proof 与父交易 `jti` 绑定。
- **完整业务参数绑定**：通用操作 nonce 额外签署 `context_hash`，覆盖额度、商户、参与人、预约时间和原因等结果影响字段；便利路由也会拒绝与路径不一致的操作名。
- **可用余额硬扣除**：转账和锁资均以 `balance - locked_amount` 检查。
- **失败原子性**：内存演示层通过账本/任务快照回滚，避免任务存储故障留下半笔余额或锁资变更；生产应替换为数据库事务和 outbox。
- **状态持久化与完整性**：核心账本（`BANK_LEDGER_STORE_PATH`）、待审批注册表（默认随会话库）、设备注册表（`BANK_DEVICE_STORE_PATH`）与审计链（`BANK_AUDIT_LOG_PATH`）均可原子落盘并在启动时重放；文件携带完整性摘要，配了 `BANK_AUTH_SECRET` 时为 HMAC，校验失败或记录无效即拒载并冻结写入，后续变更不会覆盖证据。**摘要算法由服务端配置决定，不采信文件自报的 `alg`**：否则能改写文件的人可把 `hmac-sha256` 降级为未加盐 `sha256`、在不知道密钥的情况下重算摘要，从而伪造余额，而状态接口仍报 `integrity_keyed: true`。三处存储统一走 `security.resolve_store_digest_algorithm()` 裁决。
- **登出即吊销（含在途授权）**：`POST /api/v1/auth/logout` 在服务端吊销当前出示的这一个会话（不牵连其他设备），审计留痕；客户端先吊销再清本地，网络不可用时降级为本地清除，令牌仍随短 TTL 自然过期。**签发授权 nonce 时会记录该会话的指纹，结算时复核**，因此登出或改密后，撤销前签发的授权不再能结算（此前 nonce 与会话无关，登出只切断了登录而没切断出金）。未持有会话的调用方（演示的自称身份模式）不受影响。
- **边缘防护**：请求体大小上限、`no-store`/`nosniff`/`X-Frame-Options` 等响应头在 Core 层统一设置。
- **事实型回复**：余额会校验总额/锁定/可用三者的一致性，账单和扩展结果会校验字段、数值和 `code/status`；异常响应只进入“不声称成功”分支。
- **网关入口控制**：会话令牌（`POST /auth/session`，主体覆盖自称身份头；`BANK_REQUIRE_SESSION=1` 时写操作强制）与 60 秒请求窗口限流（429 + `Retry-After`，探针与文档路径豁免，首次超限写入审计）。**限流桶取自已验证的会话主体或对端地址，不取自客户端可自选的身份头**——`X-User-Id` 是对象选择器而非凭证，用它当桶键等于让被限流方自己决定属于哪个桶（改一个头即恢复配额）。网关的演示身份短路与核心的 `demo_mode()` 现在都按调用读取 `BANK_DEMO_MODE`，关闭演示模式只需改环境变量即可同时生效。
- **行为组合熔断**：敏感操作产出加权信号（大额转账/锁资、理财申赎、卡片额度与状态变更、挂失、改密、凭证失败），6 条命名规则在滑动窗口内命中即累计评分，超阈值锁定账户并写入 `BEHAVIOR_RISK_LOCK` 审计（含评分、命中规则与信号序列）；同一请求内的重复上报按 `request_id` 去重；`GET /security/behavior/{user_id}` 提供可解释明细，锁定随窗口到期自动恢复。
- **人机协同**：LangGraph `interrupt()` 可暂停黄色/红色流程并取消。
- **回归测试基线**：`tests/` 共 17 个文件（341 个用例）。`test_core_api.py` 覆盖未知账户、金额边界、风险阈值、伪造/篡改/重放 token、红区 MFA 绕过、锁资，以及**预检后冻结账户/卡片仍拒绝结算且余额不变**的真实负路径；`test_login.py` 覆盖 argon2id 口令登录、枚举不可区分、失败计数熔断、凭证轮换吊销会话与**登出只吊销当前会话**。
- **安全回归扩展**：`test_security_regressions.py` 覆盖身份缺失、预约/AA 动态红区、上下文篡改、人脸票据绑定与单次性、审计链路与轮转校验、路由混淆、请求大小和失败回滚；`test_concurrency.py` 用真实线程验证**同一 Idempotency-Key 并发只记一笔（第二次回放同一流水号）**、**同一 nonce 并发只有一次结算（另一次 TOKEN_REPLAY）**、并发锁资只占用一次。

## 4. 已知风险清单与优先级

### P0（生产上线前必须修复）

1. MFA 的 OTP/人脸仍是本地模拟因子（人脸已升级为挑战-签名一次性票据，不再接受布尔自证）；生产需真实生物供应商、设备绑定与密钥托管。
2. 本地演示身份支持 argon2id 口令登录（可选登录 OTP），签发会话需通过 `/auth/login`；免口令的演示会话端点 `/auth/session` 由 `BANK_DEMO_MODE` 门控。共享/生产环境必须关闭演示模式、开启 `BANK_REQUIRE_SESSION=1` 并接入 OIDC。
3. 会话凭证、任务队列仍为进程内存；账本/审批注册表/设备库/审计链虽可配置 HMAC 校验落盘，但运行时仍是单进程文件快照而非数据库事务，生产需迁移数据库/Redis/KMS。
4. Docker 示例未配置 TLS/WAF/限流和灾备，不得直接暴露公网；Compose 已默认要求客户端身份头，但仍必须由部署者注入随机 `BANK_AUTH_SECRET`。

### P1（答辩后产品化）

1. 日累计按日期分桶并计入未消费 nonce 预留；多实例仍需数据库原子计数和分布式锁。
2. 已有结构化审计哈希链、请求编号决策链路还原、可选追加文件与重启回放校验、幂等、熔断和错误脱敏；需集中告警和不可抵赖的外部存储（WORM/KMS 签名）。
3. planner.py 已完成时间过滤和事实聚合；需持续完善商户分类评测。
4. 已有注入拦截、缺槽位澄清、DAG 驱动执行（`PlanExecutor` 依赖顺序推进）、结算失败补偿核对与人工接管；需持久化工作流执行器和跨实例补偿调度。
5. 分析沙箱当前采用 AST 与短生命周期 worker 的演示隔离，并限制表达式节点、幂指数、整数位数、输入/输出大小和超时；账单聚合（总额/退款/类目分组）已通过 `planner.analyze_transactions` 真正接入沙箱执行，`analysis_engine` 记录实际路径，进程池不可用时降级为受限线程并如实标记；生产仍应放入独立容器或 microVM、只读文件系统和无网络命名空间。

### P2（产品化）

1. 生日联动当前创建“生日前两天提醒”和鲜花/蛋糕订单草稿；订单到期只进入 `WAITING_USER`，不会在 Mock 中真实下单，生产需接入供应商、通知和补偿。
2. 密码修改当前只做“凭证版本轮换”演示，不接收明文密码；生产必须由 IdP 完成密码复杂度、旧密码校验、哈希和设备绑定。
3. 加密传输/密钥轮换、速率限制、设备指纹、灾备和数据留存策略。
4. 当前沙箱是 AST + 受限进程示范；生产需容器/microVM、seccomp 和网络隔离。

## 5. 测试与验收矩阵

| 测试 | 预期 |
| --- | --- |
| 0、负数、NaN、Inf 金额 | 400/422，余额不变 |
| 日累计恰好 1000 | YELLOW |
| 日累计超过 1000 | RED；无 MFA execute 为 401/403 |
| 缺失/伪造/过期/重放 token | 拒绝且不记账 |
| token 改金额/收款人/付款人 | 拒绝且不记账 |
| 锁资超过可用余额 | 拒绝；不可出现负可用余额 |
| 冻结账户/卡片写操作 | 预检与执行双点拒绝（`ACCOUNT_LOCKED` / `CARD_BLOCKED`），余额不变。卡片状态与日限额现在也在预检解析：钱包里无可支付卡、卡号有歧义（多张 ACTIVE）或指定卡状态不允许时，预检即拒绝，不再让用户走完确认与 MFA 才在结算失败 |
| 登出/改密后在途授权 | 预检+确认后吊销会话 → 结算拒绝（`SESSION_REQUIRED`/`SESSION_REVOKED`），余额不变 |
| 多卡账实一致 | 日限额的检验卡与记账卡是同一张（指定卡号即按该卡生效），卡片页显示的已用/剩余与实际扣减一致 |
| 联系人簿「用手机号认领」 | 只凭输入手机号建立的关联是**临时**的：可向该联系人付款，但不可据此代为扣款（AA 分摊回 `PARTICIPANT_NOT_AUTHORIZED`），也不回显号主真实姓名；号主把对方号码录入自己的联系人簿后才升级为已确认 |
| 落盘文件篡改 | 改内容且**按声明算法重算摘要**仍被拒；已配置 `BANK_AUTH_SECRET` 时拒绝任何非 `hmac-sha256` 声明的文件 |
| 并发重复请求/网络重试 | 至多一笔记账：同一 Idempotency-Key 并发回放同一流水号；同一 nonce 并发仅一次成功，另一次 `TOKEN_REPLAY` |
| Prompt injection/LLM 异常 | 只执行白名单动作或澄清，不得写账 |

执行方式（依赖安装后）：

```bash
python -m pytest -q   # 全量测试文件与用例数见 README 的"协作者上手"一节
```

当前仓库是内存沙箱，测试 fixture 会在每个用例后恢复全局状态；迁移数据库后应改为事务回滚或专用测试数据库。

## 6. 整改路线

1. 将内存状态迁移到数据库/Redis，配置真实身份、MFA、TLS 和密钥轮换。
2. 继续以严格 Schema、白名单工具和事实校验约束模型；低置信度请求只澄清。
3. 将任务 DAG 接入消息队列、定时执行器和补偿/人工队列。
4. 在 CI 中执行 pytest、ruff/mypy、依赖漏洞扫描、SAST/DAST、SBOM 和镜像扫描。
