# 核心算法

安言把语言理解、证据计算和执行授权拆开。模型提出候选结构，程序检查协议与来源，Core 决定是否允许业务提交。本文可以独立阅读，路径以源码根目录为基准。

术语：DAG 为有向无环任务图；MFA 为多因子验证；OTP 为一次性验证码；HMAC 为带密钥的消息认证码，用于验证参数和凭证未被篡改。

## 处理阶段

| 阶段 | 输入 | 输出 | 主要拒绝条件 |
| --- | --- | --- | --- |
| 理解 | 本轮原话、同主体上下文、能力和规则 | 行为、目标、对象、字段、讨论命令 | 对象冲突、协议越界、金额歧义 |
| 讨论 | 本人未完成任务和当前表达 | 补充、更正、暂停、恢复或取消意向 | 无唯一匹配、只是询问规则、历史叙述 |
| 取证 | 目标和固定只读工具 | 本人记录、规则、来源与缺口 | 越权、读取失败、不完整集合 |
| 回答 | 有效证据与草稿 | 核验后的逐项目标状态 | 无来源金额、漏答、错误成功声明 |
| 执行 | 原审批、原参数、确认和必要证明 | 已保存回执或明确失败 | 授权过期、参数变化、验证或持久化失败 |

LangGraph 节点为 `intent_parser → risk_checker → human_review / executor → responder`，复合流程通过 `workflow_next` 推进。查询不会因为经过同一张图就取得写权限。

## 目标协议与上下文

每轮最多五项目标，包含 `id`、`act`、`resource`、`question`、`fields`、`subjects`、`topic` 和 `requires_record`。行为只允许 `QUERY`、`EXPLAIN`、`ACTION`、`UNSUPPORTED`、`UNCLEAR`；字段来自资源白名单，每目标最多八个不重复字段，对象集合最多五项。

```json
{
  "id": "q1",
  "act": "QUERY",
  "resource": "cards",
  "question": "查询这张卡的日额度",
  "fields": ["daily_limit"],
  "subject": "CARD-001",
  "subjects": ["CARD-001"],
  "topic": "card",
  "requires_record": true,
  "needs_subject": false
}
```

示例只说明结构，不证明卡片存在或用户有权访问。主体来自登录会话，用户原文和最近已核验对象用于解析引用；账户状态必须重新读取。

同主体最多保存四项未完成讨论。`RESUME`、`FILL`、`CORRECT`、`PAUSE`、`CANCEL` 必须匹配当前表达和本人任务。补齐“李四那笔转账”的金额可以形成新提案，但不能恢复旧确认；讨论状态不保存 OTP、签名或可继承的执行权限。否定、引用、条件句和流程咨询限制动作，不能因出现“转账”两个字就执行。

## 规则检索

`banking_knowledge.py` 维护知识与能力，`banking_rules.py` 导出人读说明和 JSON。当前知识快照为 `2026-11-01.2`，105 条记录包括 75 条业务规则和 30 项能力。修改后必须重新生成并审查语义；同源只能证明版本一致。

检索将标题、正文与主题别名转换为词项，弱化导航词，按词项稀有度和标题命中评分：

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
正文分 = Σ idf(t) × min(tf(t,d), 2) / (1 + 词项总数(d)/200)
标题分 = 2 × Σ idf(t)，仅计算标题命中词
总分 = 正文分 + 标题分
```

结果按得分降序、编号稳定排序，保留不低于最高分 35% 的记录，再按调用上限截取。理解前通常检索四条。无命中可以返回空集合，不拼接无关政策。自然语言匹配在本地进行，Core 回源请求只传稳定规则编号，并核对内容、版本与实现摘要。

规则说明条件，不证明本人余额、联系人、持仓或付款结果。公开产品与个人持仓分开，订阅仍通过原黄区确认，不能由通用规则工具绕过。

## 有界取证

咨询只有十二类固定只读工具：`knowledge`、`rules`、`account_context`、`balance`、`cards`、`disputes`、`transactions`、`contacts`、`wealth_products`、`wealth_holdings`、`risk_profile`、`tasks`。工具不接受任意 URL、方法、SQL 或外部主体。

```text
读取预算 B = min(10, 4 + 2 × 目标数)
最多 3 轮取证规划，最多 3 次回答草稿
同一失败读取最多重试 1 次，重试与修复共用 B
```

旧协议兼容路径仍为五次读取、两轮规划，不能混为当前目标协议的预算。逻辑读取次数也不等于底层 HTTP 请求数。

证据保留资源、对象、字段、集合范围和来源编号。同资源刷新替换旧事实，避免改写时继续引用旧值。失败、有效空集合和有记录分别表示不同状态；字段未投影不等于源记录没有该字段。

## 计算与受限表达式

金额以整数分处理。`sum`、`difference`、`count` 从登记字段和证据取数，保留操作数及结果编号；生成器只能引用已绑定结果，不能在自然语言中重新猜算。缺字段、不完整集合或单位冲突时保留缺口。

账单表达式经 AST 白名单检查，在独立进程中执行，默认约 1.5 秒超时、512 MiB 内存和 3 秒 CPU 限制，工作进程最多处理 50 项后重建。平台可用性影响资源限制，默认不允许线程回退。这里只限制语法和资源，不提供操作系统级文件、网络或租户隔离；不运行任意用户 Python。

## 生成、核验与修复

草稿只接收当前目标、必要规则与有效证据。确定性检查先核对金额、来源和执行状态，再由独立模型调用检查事实支持、切题与逐项覆盖。修复反馈可以要求补查、重算或改写，但共用预算，不能无限自我循环。

覆盖状态区分已回答、缺数据、需澄清、需确认、不支持和工具失败。部分完成不得写成全部成功。对资金回执使用确定性表达，不让生成器把预检或未知状态改写成付款成功。核验调用与生成调用独立，不代表模型偏差独立。

模型请求使用有界并发：当前池最多两项运行、八项等待。同一输入的延迟对冲最多一次，约四秒触发，共享原预算；它不是扩大候选搜索，两个已发出的请求都可能收费。原文处理预算、超时与取消统一约束重试，不以多次取最好结果粉饰稳定性。

## 风险、授权与提交

Core 依据业务、金额、当日累计、待执行授权与行为状态定级。普通查询绿色，小额转账和订阅等黄色，大额转账、挂失、申购等红色。以日累计 1,000 元为边界，600 元之后再提 600 元不能继续走小额路径。

授权用 HMAC 绑定主体、会话、操作、对象、金额分值、备注和上下文摘要、风险、唯一编号与期限。默认授权约 120 秒、网关审批句柄约 110 秒、设备挑战约 60 秒；各自有效期仍以运行配置和服务端响应为准。Core 保存明确确认，红区核对 OTP 和登记公钥的设备签名，执行时重新检查条件并消费授权。

业务在锁内校验幂等键及请求摘要。相同键与参数返回原结果，不同参数复用同键被拒绝。账本与回执持久化成功才返回成功，失败返回 503 并回滚本次内存变更。结果不明先查原回执，不自动重做付款。

## 任务依赖与撤回

DAG 每个节点声明 `depends_on`，依赖全部 `SUCCEEDED` 后才可进入检查。依赖失败保留阻塞状态，不把部分成功包装成整体完成。中断和取消只改变尚未完成的任务；预约撤销、解锁资金等仍走各自业务协议，已结算转账不支持通过回退图节点撤销。

## 如何验证

协议回归核对对象绑定、参数变化、跨主体、重复提交和状态；计算回归核对来源与分值；对话评测另行验证真实模型的理解与回答。单元测试不证明联网模型表现，独立核验不构成金融认证。仍需更多未参与开发的任务、人工复核及部署环境故障测试。
