# 核心算法说明

## 需求理解与讨论状态

输入经过范围检查，由可配置模型结合脱敏上下文识别查询、解释、办理、纠正、暂停、恢复和澄清。结构化结果必须通过能力白名单与槽位检查；金额和对象依据原文及 Core 记录核对，历史讨论不能补造授权。

讨论任务按用户、对象和缺失字段保存。插问可保留原讨论，补充后继续。复合请求拆为有依赖的步骤，每步独立预检和确认；停止意向不能撤销已完成业务。

## 多目标取证与计算

```text
识别本轮问题及所需字段
逐项绑定用户、对象和期间
检索版本化规则，按需读取本人资源
计算已核验字段，保留操作数与来源
分别标记可回答、缺失和读取失败项
```

咨询仅开放登记的十二类只读工具，资源、方法、预算和主体受程序限制。公开货架不等于本人持仓，失败不等于无记录；对象不唯一或最新结果为空时，不借旧记录扩大范围。

账单分析表达式经过 AST 白名单，禁用任意导入、属性访问和不受控代码；工作进程受期限与资源约束，安装限制失败时拒绝执行。计算结果不授予付款权限。

## 回答生成和核验

```text
草稿 = 模型生成(本轮目标、当前规则、已核验证据)
程序检查(金额、字段、编号、主体、操作完成声明)
独立语义检查(切题、覆盖、依据)
失败时在共享预算内定向补查或改写
仍失败则准确报告已知信息和缺口
```

独立核验不保证绝对正确，同一模型仍可能出现相关错误。资金结果以 Core 回执为准，自然语言判断不能替代执行。

## 风险与一次性授权

Core 按业务、金额和行为计算 GREEN、YELLOW、RED。查询通常为绿区；小额转账等黄区需确认；大额累计转出、调额、理财申赎、冻结和挂失等红区另需 OTP 与设备签名。使用 `Decimal` 核对金额，当日累计边界为 1000 元，行为信号可升级风险。

授权绑定主体、业务、对象、金额、有效期与 nonce。执行端重新检查，不能通过更换模型或客户端“已验证”声明降级。Keystore 私钥签署服务端 challenge，Core 用登记公钥验证。

## 幂等、提交与核对

同一提交的重试复用幂等键。预检通过、请求发出或界面进度都不等于业务成功，Core 持久化后才返回成功回执；结果不明时只读核对原操作，不能自动重付。

联系人使用前置确认。打开或取消弹窗不提交，确认后立即调用删除接口，回执丢失时只读核对。列表请求受版本检查约束，删除前发出的旧响应不能恢复已删除记录。

## 验证方法

单元/API 回归覆盖意图边界、跨账户访问、参数篡改、重放、写盘失败回滚和持久化重载；设备测试同时检查用户界面与真实接口记录。规则模式、联网模型诊断和重复任务评测分别统计，不把局部通过当作完整可靠性结论。
