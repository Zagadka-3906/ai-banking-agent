# 测试用例与复现步骤

交易列表追问覆盖 `ALL`、月度和指定日期范围，以及新日期、数字天数覆盖旧范围；最新空列表不回找旧月份，其他用户观察不继承。完整四轮网关先展示全部八笔，再澄清未指定单笔，最后分析整批可疑线索，必须保留原范围与八笔输入并指出实际线索，不能说只读取一笔。只问可疑子集或明确单笔时继续保留相应选择，不发起冻结或争议。

模拟用户只应查询余额时，额外加入“先不转这笔了”必须记为目标漂移；即使核对模型同时写 `faithful=true`，目标行为与实际行为不同仍阻断，原文不被改写，银行不接收该轮，不追加语义重试。

当前取消决定覆盖“不过现在决定先取消了”等命令分句，停止匹配的未完成申购及问卷；过去“我取消了／昨天决定取消了”、已申购、已成交、引用、条件、疑问、不要取消、错产品与多个产品不能触发。补金额覆盖“先不管生日联动，原转账金额补上300元”，完整网关须恢复原收款人的待确认提案且不扣款；多个原任务、不同操作、冲突金额、费用或可行性问题、条件和执行否定不能被片段恢复吞掉。

理解服务超时、容量和连接故障时，独立验证的本人未完成意向取消仍可退出问卷，财务及授权状态不变；错对象、并行查询、条件、已执行业务、不要取消、跨主体、正在审批及新转账均保留失败，不通过本地路径办理。

精确理财入口模拟模型误判为不明确、社交或申购，均须读取公开货架，没有问卷、审批或资金变动；自由风险解释保留模型语义。当前放弃回归覆盖前句“已经了解／想清楚”、后句明确不冻结或转账，已执行业务、历史取消、条件、引用和否定取消仍拒绝。设备推荐单击测试先关闭登录键盘并确认窗口焦点、可见且启用，再做一次点击并检查新增原文消息；失败保留布尔状态诊断，不增加重试点击或放宽点击即发送要求。

读取结果证据测试覆盖余额、流水、卡片、联系人、工单、产品、持仓、风险档案与待办：实际读取失败可支持解释失败含义，但不能满足任何个人记录查询。对象未绑定不冒充服务故障，失败后成功以新记录为准，旧失败不作为新轮的当前尝试；篡改结果正文、来源、字段或移除失败依据均拒绝。完整网关覆盖部分查询成功后的连续追问，以及核验模型即便同意也不能将失败冒充没有任务。

评分器结构诊断覆盖错层字段、字符串布尔值、非整数自然度、越界分值、空理由、超长理由及缺字段；均须保留字段错误、只调用一次并维持错误。未知字段名及敏感原文不进入诊断，目标预检与阶段评分分开记录。合法负分原样保留；发布检查拒绝缺失诊断版本或逐项记录，以及带结构错误的伪造 PASS。

未指定收款人的讨论测试核对目标、金额、日期缺项确实留存，且没有授权字段。完整网关从纯预约准备说明进入“先取消这个意向”，要求停止未完成讨论且财务不变；其他业务的单独讨论不能被误取消，多业务并列与多个相同预约讨论均需澄清。查询含义、流程、疑问、条件、已完成和不要取消不能变成停止指令。

预约停止回归重放“先不预约转账了，这笔预约转账帮我取消”，完整网关要求停止待补金额／日期的讨论、无新增审批且财务不变。对象前置的同类分句另覆盖转账、申购、调额；多个匹配任务、已完成交易、Core 任务、条件、疑问、引用及不要取消仍拒绝。单纯否定预约同样不能进入执行。

语义补槽验证没有恢复词的“转账金额是300元，先帮我看看，暂不确认”仍恢复原收款人并展示审批；仅在本轮模型行为与字面业务相符时使用唯一任务。模型输入不明确仍澄清；独立查询目标、范围外、不同收款人、多任务、条件、咨询、停止办理和歧义金额不能触发。显式恢复与先前生日话题的回归保留。组合否定覆盖“不再继续办理／不要再继续办理”等，不能因连续副词丢失停止意图。

原始协议反例模拟模型 FILL 正确引用原任务、ACTION 目标带原收款人但本轮只补金额，完整网关须保留对象并生成正确待确认提案。有效命令、无命令但唯一匹配以及伪造命令被拒后走独立唯一任务校验分别检查；查询／解释／不明确／不支持目标不能借讨论引用绑定本人记录，所有资金仍等待确认。

停止办理的负向网关轨迹模拟模型误标 ACTION／SLOT_REPLY／EXPLAIN，字面“先不办理”仍须停止匹配的未完成讨论并明确尚未执行，不能返回无关咨询或生成提案。独立余额查询、费用说明、错收款人、条件及范围外不能被此入口吞掉。

跨话题补槽覆盖“补300元／补三百元”及等待确认卡，完整网关要求保留原收款人、金额正确、只创建提案；多个待办、条件、费用咨询、不同金额和“先不办理”不得恢复。对象澄清覆盖交易、卡片、产品及任务，候选只来自同主体最近实际展示编号；跨主体、空选择、旧编号、其他资源及范围外问题不能泄漏或扩展。完整网关验证查询后对象不明仍询问对应交易编号、无新审批或财务变化。

格式与归属回归覆盖卡片尾号中的普通空格、不换行空格及全角数字，完整网关核对实际渠道、逐项完成且无财务变化；不同尾号、较长编号与编号前缀不能误绑定。公共货架与空本人持仓分别检查记录归属和数量说明。现代查询后切回兼容追问必须重新核验唯一展示记录，底层整批编号、未展示异常、空结果、多个候选和其他主体不能提供新的绑定依据。

逐轮评分回归验证环境快照深拷贝不受后续步骤及结束检查修改、当前阶段看不到后续问题／目标／余额、阶段编号错误不重判，以及发布检查拒绝旧版、空值、错轮或缺失快照。合法负面判断只调用一次，不把评测提示修订算成银行业务通过。

字段投影契约通过完整网关验证生成与审核收到同一份所问字段及实际缺口：查询类别与可用余额不能把未投影金额说成原账本缺少金额；真正要求但缺失的金额仍登记缺口。取消回归新增“我前面想申购零星宝，现在决定取消了，先不办了。”，保留历史完成、疑问、条件、引用、错对象及范围限制。

省略取消对象的测试覆盖末尾裸指令、本人唯一问卷或讨论匹配、无待办仅确认不继续，以及范围外标签不得取消任务。申购、赎回、转账、调额共用同一验证入口；完整网关检查无财务变化，不以“取消”关键词或固定回复模板代替成功证据。

取消语气的分句回归覆盖“决定先取消了，麻烦帮我取消这次申购”等表达，并扩展到赎回、转账、调额；当前指令不得被前一分句的完成语气覆盖。完整网关轨迹要求停止匹配的未完成意向且无审批或业务写入，已成交、已扣款、过去完成、错对象及条件／疑问／引用仍拒绝。真实模型的原句重放单列为固定用户诊断，不计作模型用户正式验收。

评测传输 v4 覆盖模拟用户消息结构不符仅共用一次格式修正、二次不符仍为错误，以及评分器结构不符不得重试；并沿用 v3 用实际 SDK 的本地 HTTP 传输覆盖超时、连接失败、408/429/503 重发、连续故障停止、认证与额度不足不重试、格式异常与接口异常组合最多三次调用。核验相同输入、JSON 绑定、思考参数、完整计量及原始错误不进入诊断。合法负面判定仍仅一次评分；发布检查拒绝虚构诊断、错误顺序、超次数、未知错误类型和成功记录中的终止异常。

设备回归运行器每次使用新输出目录，运行前移存上次 JUnit/protobuf 结果，成功、失败和超时均保存本次实际结果；验证只读取本次快照，编译失败不能拿旧通过结果补齐。`test_android_regression_runner.py` 覆盖这四种路径与私有命令不进入异常。`UiClosureComponentsTest` 验证任务查询加载期间返回不触发业务，业务提交期间返回被保护，提交结束后可退出；`ScenarioAccountIsolationUiTest` 继续验证晚到的旧 HTTP 401 不能注销新登录，设备撤销不能被换新密钥绕过。撤销通知在消费前由状态流观察，不依赖已被界面清空的瞬时字段。

`test_stability_load_contracts.py` 使用真实线程验证单、三、十个登录会话的主体隔离和只读不写账，以及模型执行器最多两个执行、八个排队、额外请求拒绝和调用上下文隔离。`test_stability_response_loss.py` 在 Core 已实际提交转账后丢弃首次响应，检查同一幂等键重试、双方余额只变化一次且仅有一对流水。它们使用隔离本机环境，不是线上容量或物理断网证明。

`test_stability_process_restart.py` 启动独立监听端口、严格登录和临时持久化的真实 Core，完成转账后强制终止进程，再启动另一进程。检查双方余额、仅一对新流水、无需旧授权的本人幂等回执重放及持久化健康，不触碰常规后端或用户数据。

`test_dialogue_task_evaluation.py` 验证成功及硬失败提前停止的轨迹，均将每阶段实测约束送给事后评分器；正面语义评分不能覆盖硬失败，全部硬检查通过也不能覆盖漏答。模拟用户仍只能接收公开目标，不读取实测账本和评分标准。

Flash 与缓存修订用真实 SDK 本地传输验证思考参数不会被费用代理或 JSON 绑定丢弃；未知模式显式拒绝。发布测试拒绝缺失或混用推理配置，缓存汇总测试按 token 加权。实际调用成绩与本机检查分开记录，见验证记录。

无符号金额的日期边界由 `test_current_answer_evidence.py` 覆盖：量词与扣款类型关联的 19.90、12.50、10.25 等小数不虚构日期；原句带明确日期范围时保留该范围，日期关系与非法点分日期仍校验。`test_shared_input_contracts.py` 重放无“元”字的可疑订阅代扣线索提问，检查实际 GET 流水、无日期澄清、全部 Core 调用只读，账本不变且没有审批。

`test_goal_field_fidelity.py` 核对取数前的字段复核不接收初次字段或改写问题、不能扩大读取字段、原目标不可变、错误复核保留原查询、明确缺字段仍拒绝完整成功，以及计算字段不可移除。`test_dialogue_task_evaluation.py` 另验证模拟用户将办理改成纯流程咨询时，在执行前记为评测偏移；正常办理措辞不被此检查拦截。此类测试验证协议边界，不能代替真实模型重复任务。

`test_simulator_goal_preflight.py` 验证查询、补槽、提案都先核对阶段目标；取消目标却生成继续办理时，即使忠实度布尔值错误为真，行为不一致也不能调用 Agent。格式异常或超时保留提问并停止，不重新抽样；合法输入之后的真实 Agent 失败仍为失败。另验证核对只接收公开目标、已知事实及此前用户消息，使用 JSON 模式且单次计入评委费用。`test_dialogue_release_gate.py` 覆盖旧检查版本、脚本用户、缺轮、重复轮、缺少检查、反向行为、目标或问题摘要失配及缺少试验级记录，均不得发布。

阶段目标契约另覆盖背景写有“后来决定取消”、当前阶段却明确要求办理的情形：保留完整背景事实，同时将当前阶段目标作为唯一行为来源；不向预检泄漏助手答复、私有标准或固定问句。真实 Flash 评委校准另记正反例与每次调用费用，不并入银行完整任务成绩。

`test_feasibility_and_entity_binding.py` 验证额度咨询后的范围追问仍经过模型理解，即使模型错判动作也不创建审批。`test_requested_amount_evidence.py` 区分多项用户自报金额与账户、合计事实：每项输入在本回答明确归属后可自然重复引用，后置标注也可核验；归属不跨回答或金额，不可改称实际额度、余额、获批结果、无来源的新金额或已核验计算；输入金额最多五项，编号不能提供金额。`test_answer_repair.py` 通过网关检查引用表合并、定位反馈、无需补查的改写，以及复用条款前缀后仍重新读取变化的余额。

收款人绑定测试另覆盖恢复提案中的重复姓名、业务对象后缀与当前 Core 身份一致；未知对象、不同真实身份、同名不同账户和真实较长标签不能被语法修正吞掉。网关检查恢复请求只创建待确认提案，不改变账本。

`test_readonly_daily_counters.py` 验证缺失、过期、当日日期桶的实际 GET 不修改账本或磁盘；推进时钟跨午夜后只改变返回的当日视图。另通过真实确认与转账验证跨日后的两笔累计、重启恢复，以及写盘失败回滚旧日期和金额、恢复后重试。实际转账和预约结算均走同一日累计记账入口。

`test_evaluation_transport.py` 用真实 SDK 与本地 HTTP 传输核对 JSON 格式、输出上限、费用代理和接口拒绝后不退回自由文本，验证过程不访问付费接口。评测格式修复最多一次、保持任务视图、两次调用均计量并记录；连续畸形仍报错，合法 JSON 的低分、缺字段或目标漂移不重试。发布检查拒绝旧版本和遗漏记录。卡片尾号测试区分当前已引用身份、错误/未引用尾号与金额；诊断测试拒绝跨请求、任意错误正文和私有载荷。实际模型成绩另见验证记录。

现行测试说明同步于 2026-10-29，最新线上版本及多目标共享链路验收见验证记录。已执行数量与每轮版本只引用[验证记录](验证记录.md)顶部；本文列出的用例和命令不等于本次文档更新又执行了全部验收。

`test_pending_business_intentions.py` 覆盖第一人称明确办理后追问步骤、可行性与否定不进入办理、保留非执行取消行为，以及申购缺金额或问卷被插问暂停后取消原意向的真实网关流程。反例包含错产品、多产品、多个匹配任务、主体切换、无原任务、历史叙述、条件、引用与撤单规则咨询；取消不能签发授权或改变账本。

取消回归同时覆盖“那我决定”“那就”“那么”“所以”“因此”等连接表达，以及带这些表达的疑问和条件反例；完整网关流程重放承接前文的取消句，验证问卷清除且没有新增授权或业务变化。

另覆盖省略主语的“决定取消”及前句已点名对象、后句仅说“这次申购意向”的承接；两个产品的未完成讨论只能取消明确匹配者，错产品或跨分句多产品不能被丢弃后误取消。`test_evaluation_costs.py` 用两个共享费用账本的 CLI 批次验证启用 `--stop-on-failure` 后首个失败或模拟偏移错误即停止，第二批不再启动付费工作进程，原始错误及未运行数保留。

当前业务指代回归覆盖“仍想申购，但现在决定先取消这次申购”以及本次、这笔的表达；同一取消路径验证转账、调额和赎回的既有未完成讨论。无原任务、多任务、错产品、真实预约任务撤销、条件、疑问、引用和已完成业务均不能误清除讨论。“不用取消”“不想取消”“不要帮我取消”等否定取消动作时也须保留原讨论。完整网关重放本轮真实失败原句，检查问卷及未完成意向清除，授权与账本不变。

理解误标为 `ACTION` 时仍阻止当前业务取消句发起新办理；风控测试绕过理解层，独立验证不访问 Core 取得授权。`test_undo_and_card_channel.py` 同批验证“撤销这笔预约”等原有解析，以及创建预约后经过真实黄色审批撤销，防止将实际撤销错误拦成普通咨询。

取消谓语后置的测试覆盖“之前想申购的意向也一起取消”“待确认申购请先撤销”等顺序，并完整重放“那我不申购零星宝了，之前想申购的意向也一起取消，先不办这个了。”。反例包含规则说明、如何取消、否定取消及历史叙述。对象提取同时验证业务名词“意向、方向、倾向”不产生人名，“向李四转账”“向刘宗屏转账”仍识别真实姓名，字面联系人标签“意向”不因修正而被删除。

**范围：** 本机 Mock Core/Gateway、Android 模拟器与虚构账户。测试前按 [README](../README.md) 安装依赖并启动服务。涉及资金的用例会修改 Mock 账本：请在隔离测试环境执行，或重启未配置持久化路径的 Core 恢复演示种子。自动化测试通过 `tests/conftest.py` 隔离本机 `.env` 与真实持久化文件。

## 查询与办理边界验收（2026-10-24）

`tests/test_inquiry_boundaries.py` 固定让模型错误返回反诈或冻结意图，复现“分析本月账单 → 那6笔可疑交易帮我查下 → 争议工单进度怎么查 → 争议工单多少有结果”。分别核对实际交易和本人已有工单，余额、卡片、争议记录及授权表与执行前完全相同。覆盖有/无工单、他人工单、流程与时效问题、含糊盗刷查询、“我的卡被盗刷了吗”“这是盗刷吗”等疑问、真实保护仍需红区确认、重复保护关联旧工单、回指、脱敏、记忆上限及主体切换。

## 扩展对话回归（2026-10-25）

2026-10-25 扩展对话回归见 `tests/test_conversation_quality.py`：以合成流水复现后台发现的“查这笔转账记录”“那5笔交易”“能撤销争议工单吗”，另测实际卡片状态、按问题选择余额/影响事实、普通缺槽请求插问后继续、待审批期间查询及错误恢复。确认、取消、过期后重投插问必须仍是查询，原写操作至多执行一次。生成回答可自由组织已有证据，但不得引入新金额、编号、事实或删除必要限制；无效 Core 回执不得进入模型回答层。金额由服务端绑定，范围、问题覆盖和语义支持另行核验。

## 写盘失败与恢复验收（2026-10-24）

`tests/test_ledger_persistence.py` 分别模拟打开、fsync 和替换失败，覆盖有/无幂等键的转账。必须返回 503 / `LEDGER_PERSISTENCE_FAILED`，余额、流水、任务和业务回执与执行前一致；重启读取旧快照不能出现失败交易。存储恢复后，新授权可复用失败的执行幂等键，成功回执与余额一起恢复。成功审计必须在文件替换后发布；失败请求不能留下业务成功审计。

`tests/test_task_persistence.py` 覆盖预约扣款、取消、接管、手动到期推进和后台调度写盘失败；失败后任务保持可重试状态。`tests/test_operation_replays.py` 覆盖黄区取消订阅、红区冻结卡片的回滚，并验证旧授权仍不可重放。`tests/test_agent_gateway.py` 检查 Gateway 返回 `business_status=FAILED` 与真实失败原因。损坏快照被拒绝后，后续业务写入返回 `LEDGER_STORE_BLOCKED`，原文件保持不变。
