## 2026-11-03：本地面板端口探测修复

GitHub Ubuntu 后端检查在新增账户时返回 503，同一集成测试的清理阶段也把端口判断为未释放。原探测使用排他绑定，POSIX 上已关闭 HTTP 连接的 `TIME_WAIT` 状态也可能被识别为端口占用，使停止后的服务无法重新启动。

POSIX 探测现采用与 Uvicorn 一致的 `SO_REUSEADDR`，Windows 保留原判断，避免其不同的端口共享语义。新增实际套接字回归，分别核对仍在监听的外部服务不可用，以及连接进入 `TIME_WAIT` 后已停止的服务端口可复用；不结束或接管外部进程。

Windows 本地面板、演示账户和运维回归合计 **47 passed、1 skipped**，跳过的是仅针对 POSIX 的 `TIME_WAIT` 用例，需在 Linux CI 执行。改动文件 Ruff、全量 mypy、规则导出和文档路径检查通过。实际 Linux 结果以本修复提交的 Actions 记录为准，保留下面原失败记录。

联网对话报告绑定当时模型、推理配置、数据、评分协议与费用账本。评分修订、任务副本和重跑不能覆盖旧失败，未运行与错误不得算成功。[多轮评测协议](多轮任务评测.md)

## 发布判断

稳定候选必须按[稳定验收标准](稳定验收标准.md)检查全部冻结证据、故障、设备、长期观察与人工复核。一次健康检查、构建成功、单例演示或高模型分均不能替代。

GitHub CI 显示对应提交的自动检查；模型费用、真实设备和线上观察仍以独立证据为准。没有部署记录时，不把本次推送称为云端更新。操作步骤见[测试用例](测试用例.md)与[部署手册](../deploy/README.md)。
