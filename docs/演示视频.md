# 演示视频大纲（约 4 分 45 秒，上限 5 分钟）

本大纲取代此前 6 段、无配音的版本，旧成片与原始录屏已删除。新版加入语音办理、对话回退、卡片交易渠道和安全拦截，配中文旁白与字幕。

## 一、整体规格

| 项目 | 规格 |
| --- | --- |
| 时长 | 4:45，留 15 秒余量 |
| 画幅 | 16:9，1920 × 1080，30 fps，H.264，码率约 8 Mbps |
| 声音 | 中文旁白（真人或高质量合成，语速约 220 字/分）；背景音乐轻柔、音量低于旁白 18 dB；点击、确认时加轻微提示音 |
| 字幕 | 中文全程字幕，思源黑体 40 px、白字、墨色 70% 半透明底条，位于画面下方 1/6 处 |
| 素材 | 全部为真实模拟器录屏，账户和交易均为虚构；不使用合成的界面或伪造的成功画面 |
| 角标 | 右上角常驻小字“演示数据 · 本机模拟银行”；使用规则模式的片段加角标“离线规则模式”，联网模型片段加“DeepSeek 联网” |

## 二、视觉与动效规范

**画面布局**：墨色 `#16131F` 背景。手机录屏放在画面左侧 40% 宽度内，外加圆角手机框和紫藤色 `#B9A9F5` 硬阴影；右侧 50% 是信息区，放标题、要点和数据卡。片头、片尾为满版设计画面。

**配色**：与 App 一致。主色紫藤，强调深紫 `#5A3EC0`；风险色只用于风险语义：绿 `#6EDC6A`、黄 `#FFC933`、红 `#FF5C4D`。

**动效节奏**（与 App 内动效一致）：

| 动效 | 用法 | 参数 |
| --- | --- | --- |
| 依次出现 | 信息区要点逐条出现 | 淡入并上移 8 px，每条间隔 120 ms，单条 220 ms |
| 推入转场 | 场景之间 | 新画面从右侧 1/12 处推入并淡入，240 ms |
| 镜头推近 | 需要看清确认卡、回执时 | 缩放到 1.6 倍并对准目标区域，400 ms 缓入缓出；停留不少于 2 秒再拉回 |
| 高亮框 | 指出关键字段（金额、风险芯片、收款人） | 2 px 描边框淡入，脉冲一次，跟随元素 |
| 点击指示 | 每次点击前 | 半透明圆点在点击位置扩散一次，300 ms |
| 计数 | 片尾数据 | 从 0 计数到目标值，600 ms 缓出 |

禁止：旋转、弹跳、3D 翻转、闪烁。系统认证画面因安全保护在录屏中可能是黑屏，此时不补画面，用字幕说明“系统验证中（受保护画面）”。

## 四、真实性要求

- 每个镜头都必须来自真实操作的录屏，回执与确认卡上的金额、收款人以 Core 实际返回为准；不剪辑拼接出未发生的结果。
- 角标如实标注使用的是规则模式还是联网模型；语音片段必须使用模拟器麦克风录入的真人声音，不能用合成音频冒充。
- 片尾数字使用[验证记录](验证记录.md)中的最新结果；68 项设备回归为 2026-10-15 的结果，若录制前已重跑，改用新结果。
- 字幕和画面中不出现设备 PIN、会话令牌、API Key 或验证码以外的任何凭据；红区录制若使用测试兼容码，旁白如实说明。

## 五、录制准备

1. 启动本机 Core 和 Gateway，确认 `.env` 中已配置 `DASHSCOPE_API_KEY`（语音镜头需要）。录制前重置演示数据，保证初始余额为 15,000 元、当日累计为 0。
2. 镜头 5 需要模拟器使用电脑麦克风：在模拟器的“Extended controls → Microphone”中打开“Virtual microphone uses host audio input”。首次使用云端识别时会出现同意弹窗；如果之前已经同意过，先清除应用数据再录。
3. 各镜头按顺序在同一会话中录制，保证当日累计的变化与旁白一致：镜头 5 转出 300 元，镜头 6 的 2000 元越过 1000 元阈值进入红区。
4. 录屏可用模拟器自带录制或 `adb shell screenrecord`，按镜头分段录制，后期统一套用上面的布局和动效。现有的 `ContestDemoUiTest` 与 `scripts/make_demo_video.py` 只覆盖旧版 6 段内容，不包含语音、回退和交易渠道，需要更新后才能用于自动录制。
