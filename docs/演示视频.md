# 演示视频大纲（约 4 分 45 秒，上限 5 分钟）

2026-10-26 同步：本文件是制作脚本，不代表已交付新版成片。线上修订的片尾数字及版本统一引用最新实际记录，见[验证记录](验证记录.md)。画面需展示模型解释能力与独立确认边界，咨询不能剪成冻结或建单成功。

制作目标为语音办理、连续咨询、对话回退、卡片交易渠道和安全拦截，配中文旁白与字幕；现有素材须按当前脚本重新核对与录制。

## 二、视觉与动效规范

**画面布局**：浅灰 `#F0F4F9` 背景。手机录屏放在画面左侧 40% 宽度内，外加圆角手机框和柔和投影；右侧 50% 是信息区，放标题、要点和数据卡。片头、片尾为满版设计画面。

**配色**：与 App 一致（参照 Gemini 移动端风格）。白底、浅灰卡片 `#F0F4F9`，主色蓝 `#0B57D0`；品牌渐变蓝 `#4285F4` → 紫 `#9B72CB` → 玫红 `#D96570` 只用于品牌标记、问候语和标题强调；风险色只用于风险语义：绿底 `#C4EED0`、黄底 `#FFE7A8`、红底 `#FAD2CF`。

**动效节奏**（与 App 内动效一致）：

| 动效 | 用法 | 参数 |
| --- | --- | --- |
| 依次出现 | 信息区要点逐条出现 | 淡入并上移 8 px，每条间隔 120 ms，单条 220 ms |
| 推入转场 | 场景之间 | 新画面从右侧 1/12 处推入并淡入，240 ms |
| 镜头推近 | 需要看清确认卡、回执时 | 缩放到 1.6 倍并对准目标区域，400 ms 缓入缓出；停留不少于 2 秒再拉回 |
| 高亮框 | 指出关键字段（金额、风险芯片、收款人） | 2 px 主色蓝圆角框淡入，脉冲一次，跟随元素 |
| 点击指示 | 每次点击前 | 半透明圆点在点击位置扩散一次，300 ms |
| 计数 | 片尾数据 | 从 0 计数到目标值，600 ms 缓出 |

**App 内动效**（录屏时会自然出现，后期不必再加）：

| 位置 | 动效 |
| --- | --- |
| 首页问候 | “你好，我是安言”的渐变色从左向右扫入；“今天想办点什么？”随后淡入上移；四张快捷卡片依次上浮，最后出现风险等级说明 |
| 侧边栏 | 每次打开，各入口从左侧依次滑入 |
| 消息 | 用户消息从右侧滑入；安言的回复淡入上浮，风险芯片随后弹出；推荐问题依次出现 |
| 处理中 | 品牌标记旋转，“安言正在为您处理…”文字上有渐变流光 |
| 金额 | 回复卡片里的大额数字、卡包里的可用余额只在第一次出现时从 0 计数到实际值；返回对话、滚动回看或再次打开卡包时直接显示金额（读屏和自动化测试始终读到最终金额） |
| 风险光效 | 只在黄区、红区等待确认时出现：光从屏幕左右两侧中部同时亮起，沿边缘向上、向下延伸，在屏幕顶端和底部中间交汇；相近色调的渐变光保持原位，柔和发光，等待期间缓慢呼吸，确认或取消后淡出，办理完成后不会再亮一次。绿区不出光效 |
| 办理结果 | 确认后的办理完成时，结果页自动从下方升起：绿色圆盘带柔和光晕弹出，对勾一笔画出，随后一圈波纹向外扩散两次；标题、状态标签、回执卡片和下方按钮依次浮现。失败时叉号两笔画出，待核对时显示转动的圆弧。查询类回复不弹结果页 |
| 确认卡 | 确认卡上浮出现；风险芯片缓慢呼吸；倒计时进度条平滑缩短，最后 15 秒变红 |
| 输入框 | 发送按钮可用时轻微弹出；录音时麦克风周围有扩散的波纹 |
| 风险测评 | 进度条平滑前进，每道新题从右侧滑入 |
| 结果页 | 状态图标由小放大出现，标题随后上浮 |

系统设置中关闭动画后，以上动效全部停用，界面直接显示最终状态。

禁止（后期合成部分）：旋转、弹跳、3D 翻转、闪烁。系统认证画面因安全保护在录屏中可能是黑屏，此时不补画面，用字幕说明“系统验证中（受保护画面）”。

## 四、真实性要求

- 每个镜头都必须来自真实操作的录屏，回执与确认卡上的金额、收款人以 Core 实际返回为准；不剪辑拼接出未发生的结果。
- 角标如实标注使用的是规则模式还是联网模型；语音片段必须使用模拟器麦克风录入的真人声音，不能用合成音频冒充。
- 片尾数字和执行日期统一引用[验证记录](验证记录.md)顶部的本轮结果；历史记录不能作为当前版本重新执行的证据。
- 字幕和画面中不出现设备 PIN、会话令牌、API Key 或验证码以外的任何凭据；红区录制若使用测试兼容码，旁白如实说明。

## 五、录制准备

1. 使用独立录制环境启动 Core 和 Gateway，配置 `DEEPSEEK_API_KEY`（联网咨询镜头）与 `DASHSCOPE_API_KEY`（云端语音镜头）。以新建隔离账本初始化种子，核对初始余额为 15,000 元、当日累计为 0；不要重置共享服务器的测试数据。
2. 镜头 5 需要模拟器使用电脑麦克风：在模拟器的“Extended controls → Microphone”中打开“Virtual microphone uses host audio input”。首次使用云端识别时会出现同意弹窗；如果之前已经同意过，先清除应用数据再录。
3. 各镜头按顺序在同一会话中录制，保证当日累计的变化与旁白一致：镜头 5 转出 300 元，镜头 6 的 2000 元越过 1000 元阈值进入红区。
4. 录屏可用模拟器自带录制或 `adb shell screenrecord`，按镜头分段录制，后期统一套用上面的布局和动效。
