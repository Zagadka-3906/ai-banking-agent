# Android 结果页检查与修复（2026-10-15）

本次纳入原有未提交的 Android 结果页、聊天卡入口及审批文案，检查它们与登录、审批、对账和导航的衔接。独立设计稿 `banking-agent-ui/` 与图标素材 `output/` 不参与 Android 构建，保留在工作区。

## 修复内容

| 问题 | 修复 |
| --- | --- |
| 打开旧结果页后审批倒计时重新开始 | 审批截止时间始终留在组合中，跨结果页及 Activity 重建仍沿用原截止时间 |
| 结果页看不到错误通知 | 结果页与聊天页共用 Snackbar；核对失败另在对应回执上保留原因和只读重试入口 |
| 旧核对响应覆盖新审批或忙碌状态 | 核对任务固定所属交互版本，只有仍属于最新一轮的回执才能推进当前流程；其他响应仅更新对应历史行 |
| 余额快捷回调可能替换正在确认的请求 | ViewModel 再次检查登录、忙碌、审批及问卷状态，避免过时的按钮状态绕过限制 |
| 部分结果标题过度承诺 | 空提醒任务不再显示已安排；复合操作保留各项待付款说明；凭证更新、风险测评和争议保护使用对应文案；未知响应提示先核对结果 |
| 审批响应解析异常可能崩溃或误报为签名失败 | 保留当前审批并显示结果待核对；仅在提交审批前的本机验证失败使用设备验证提示 |
| 回执详情和小屏展示不完整 | 支持仅含回复编号的详情；缺少核对标识时明确说明；底部操作避开系统栏，长步骤在窄屏大字体下完整换行 |

结果页只提供返回、查询余额、查看待办和读取回执，不直接重新发起转账或审批。查询错误不会把原操作状态改成失败；退出和切换账号仍清除结果页与问题页状态。

## 验证方法与边界

在 Android 15 专用模拟器、独立 `scenario` 包和本机 18800／18810 服务上验证；离线模型、演示账号和独立账本，不调用真实银行或发送飞书消息。

- 组件测试覆盖返回入口、禁用状态、回执展开、缺少核对编号、错误通知，以及 320 × 480 dp、1.6 倍字体的暗色页面。检查截图和文字布局，确认末尾内容及返回按钮可达。
- 集成测试使用真实 ViewModel、HTTP、审批与 Core 结算。对账用例先完成真实小额转账，向 Core 核对操作编号、`COMPLETED` 状态及同一交易号，再由隔离测试服务补回该已完成操作的核对索引，并将本机消息标为待核对。随后暂停实际 GET 回包，验证新审批和忙碌状态不被覆盖；重试不增加转账请求。
- 审批解析错误用例单独注入 `JsonSyntaxException`，验证不可解析响应不会崩溃，也不被展示成确定的业务失败；该用例的仓库 API 为测试替身，其他集成路径使用真实本地服务。
- 复跑上一轮账号隔离回归，包括延迟流式成功、旧 HTTP／SSE 错误、旧审批闭包和真实 Android PIN 成功／取消回调。PIN 验证不代表物理指纹硬件测试。

测试控制端点只存在于隔离运行脚本中，使用每次运行的控制令牌；不修改 Core 结算或凭空生成成功回执。运行日志、截图、凭据和 APK 均不入库。
