## 第 3 页：本机系统架构（1:10）

- **画面内容**：直接重绘[技术文档架构图](技术文档.md)，保留 Android 模拟器、Gateway `:8100`、LangGraph、Core `:8000`、账本/审计五块。箭头标记 `10.0.2.2 → 127.0.0.1`，在 Core 方框加“唯一记账边界”。

## 第 4 页：AI 怎样理解一句话（1:15）

- **画面内容**：一条输入“给李四转 300 元”→ 小 JSON `{intent: TRANSFER, payee: 李四, amount: 300}` → 白名单/槽位/联系人校验 → YELLOW 预检。旁边另放“给他转一点”的缺槽分支，输出澄清问题。下方提示“模型不能调用任意银行工具”。
- **讲述词**：讲 DeepSeek 受约束意图抽取、`planner.py` 校验、已有事实优先、LangGraph 保存多轮上下文；没有模型密钥时由规则解析器继续跑，但语义覆盖会变窄。
- **动效/转场**：主路径从左到右逐段出现；缺槽分支最后出现；淡化至权限页。

## 第 5 页：三级权限与红区执行链（1:35）

- **画面内容**：上半部表格 GREEN 查询、YELLOW 明确确认、RED 确认 + OTP + Keystore 签名；突出“当日转账累计 >1000 元升红”。下半部时间线：预检 → 不透明审批 ID → 用户确认 → challenge 签名 → Core 复核 → 记账/审计。标注审批 110 秒、授权 120 秒、单次使用。
- **讲述词**：Core 独立重算风险，不能被模型或客户端降级。Android 私钥不出 Keystore，Core 只存公钥；执行端复核金额、收款人、余额和幂等键。演示 OTP 是固定值，仅用于 Mock 账户。
- **动效/转场**：先显现权限表，再逐步点亮时间线；风险升级箭头用一次颜色变化，避免闪烁。

## 第 6 页：业务演示与多轮能力（1:20）

- **画面内容**：四宫格真实模拟器截图占位：余额卡、账单分析卡、AA 待付款卡、生日模拟商户订单回执。每格加一句用户原话和 Core 返回的事实字段；中央提示“查询直接答复，变更暂停等待授权”。
- **讲述词**：串讲“查余额 → 识别周期扣费 → 发起 AA → 参与人登录并确认付款”。订阅检测结果只标记待核实；AA 发起时不扣参与人的钱。生日任务到期后再次确认，Core 才扣虚构账本并生成本机 Mock 回执。此页可插入不超过 25 秒的现场操作或静态结果。
- **动效/转场**：四格按业务顺序出现；切到测试页用硬切，形成从功能到证据的转折。
