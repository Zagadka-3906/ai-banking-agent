# 10 分钟答辩提纲

## 0:00–1:00 痛点与目标

- 手机银行入口深、操作步骤长；自然语言是更短的业务入口。
- 目标不是让模型“自由操作银行”，而是让模型理解需求、让安全策略决定能否执行。

## 1:00–2:30 产品与场景

- 绿区：余额、流水、账单异常、理财/卡片/订阅查询。
- 黄区：小额转账、预约/AA、订阅取消、虚拟卡申请、生日锁资。
- 红区：超额转账、理财申购赎回、卡片额度/挂失/解挂和密码修改。

## 2:30–4:00 技术架构

- Android APP / Streamlit（渠道网关为 IM 适配器预留）→ 意图解析 → Schema/Policy → Core API。
- LangGraph 中断/恢复；planner.py 将复合需求编译为依赖 DAG。预约/订单到期先进入 `WAITING_USER`，需要再次授权，不做无感扣款。
- Core API 与模型物理分离，账户变更只在一个事务边界发生。

## 4:00–6:00 安全设计

- 日累计 ≤1000 黄区，>1000 红区；策略由服务端重新计算。
- HMAC 签名、TTL、单次 nonce、金额/收款人/用途绑定。
- 红区 OTP + 设备 Keystore 挑战-签名票据在服务端校验；前端字段不能越权。
- 登出在服务端吊销当前会话；账本/审批/设备库可选 HMAC 校验落盘，重启不丢已提交状态。
- 审计事件哈希链、请求 ID、敏感字段脱敏、连续失败与行为组合熔断；可按请求编号还原完整决策链。
- Prompt injection 只进入拒绝/澄清分支；沙箱仅允许只读表达式（账单聚合真实经沙箱执行）。

## 6:00–8:30 现场演示

1. 查余额和今日账单（绿区自动）。
2. 老婆转 300 元：取消一次，再服务端确认成功。
3. 李四转 2000 元：展示 MFA 未完成时的拒绝，再完成测试验证。
4. 生日锁资：锁定资金、创建依赖提醒与鲜花/蛋糕订单草稿、查看任务中心。
5. 展示风险评估/产品对比、理财推荐、订阅取消和卡片状态查询。

## 8:30–9:30 工程与测试

- 17 个测试文件、341 项 pytest 覆盖金额边界、token 篡改/重放、MFA 绕过、幂等、冻结账户与卡片、持久化篡改拒载与登出吊销，并用真实线程验证并发下至多一笔记账。
- Docker Compose、健康检查、CI；无 API key 时规则解析仍可演示。

## 9:30–10:00 局限与规划

- 当前是虚构数据的单进程演示沙箱：账本/审批/设备库可选 HMAC 校验落盘、重启不丢，但仍不是生产银行；下一步接入数据库事务、OIDC、真实 MFA、消息队列和可观测性。
- 生产上线前进行法律合规、隐私、依赖许可证和红队评审。
